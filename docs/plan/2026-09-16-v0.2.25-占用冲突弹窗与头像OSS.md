## 1. 背景

三件事叠在一起：

1. **占用冲突体验**：数字员工在「员工管理」对话（`DIRECT`）时，项目协作跑到 Agent 节点会 `TryAcquireOccupancy` 失败，节点直接 failed，用户看不到「谁在忙、怎么选」。需要弹窗：继续原任务，或打断原任务改跑协作。  
2. **头像**：v0.2.24 已有 `managed_agents.avatar_url` 但无上传；需要压缩后上阿里云 OSS，并有默认图 + 圆形框。  
3. **协作画布**：Agent 节点选员工后只显示名字/引擎色，需要在节点上展示圆形头像。

当前仓库：**无 OSS SDK / 无上传接口**；占用冲突仅后端 409/节点失败，前端无「二选一」裁决。

## 3. 实现范围

### 本次实现

**占用冲突**

- 启动协作前（或节点抢占失败时）检测图中 Agent 是否被 `DIRECT` / `CLONE_INIT` / 其它非本 run 的 `WORKFLOW` 占用。  
- API 返回结构化冲突列表；前端模态二选一。  
- 「执行协作」：对冲突员工 `StopManaged` + 清占用，再启动/续跑。  
- 「继续原任务」：不启动，或本 run 标记失败/取消（见 §7-Q1）。

**头像**

- `POST /api/admin/agents/:id/avatar`：multipart 上传 → 压缩 → OSS → 写 `avatar_url`。  
- 环境变量配置 OSS（见 §4.2）。  
- 前端：圆形 `<img>`；空 URL 用默认图；设置里可选文件上传（压缩可前端预压 + 后端再压）。  
- 复制员工：沿用源 `avatar_url` 或默认（已有字段）。

**协作节点**

- `WorkflowCanvas.updateSelectedData`：选员工时写入 `data.avatar_url`（解析后的展示 URL 或原始，推荐原始 + 前端 resolve）。  
- `WfNodes` / 运行画布：Agent 节点左侧或顶部圆形头像。

### 本次暂不实现

- 头像裁剪编辑器（仅压缩 + 圆形 CSS，不做手势裁剪）。  
- 多图相册 / 换装。  
- 协作占用 vs 协作占用 的精细跨 run 移交 UI（可只展示忙碌并推荐「执行本协作」）。  
- 反向弹窗：协作跑着时管理台提问的二选一（现已占用拦截；见 §7-Q2）。

## 4. 技术设计

### 4.1 占用冲突裁决

#### 现状

```text
管理台 Ask → TryAcquire DIRECT
协作 runAgent → TryAcquire WORKFLOW
若已占用 → OccupancyBusyError → 节点 failed
```

`AskManaged` 会清掉同类 DIRECT 再抢；但 **不会**清 WORKFLOW。协作侧 **不会** 自动 StopManaged。

#### 推荐流程（启动时预检 + 强制参数）

```text
POST /admin/workflows/:id/runs
  body: { input_prompt, force_takeover?: bool }

1) 解析 graph，收集 agent_id 集合
2) 查 occupancy：若存在阻塞本协作的占用（DIRECT / CLONE_INIT / 其它 run 的 WORKFLOW）
   - force_takeover != true → 409 + { error, conflicts: [{ agent_id, name, occupancy }] }
3) force_takeover == true → 对每个冲突员工 StopManaged + ClearOccupancy
4) 再 CreateWorkflowRun 异步执行
```

前端 `WorkflowList.start`：

```text
start() → 若 409 conflicts → 弹窗
  「数字员工「小王」正在员工管理对话中」
  [继续原任务] → 关闭弹窗，不启动
  [执行团队协作] → 再 POST force_takeover: true
```

#### 运行中撞车（补充）

若启动时员工空闲，跑到节点时用户已在管理台开聊：

- **推荐**：`runAgent` 遇 `OccupancyBusyError` 时，不立刻 failed；将节点/`run` 置 `waiting`（或复用 `waiting` + fail_reason 文案「员工忙碌待裁决」），前端全局浮层（可挂在 `WorkflowPermOverlay` 旁）展示同样二选一；  
  - 选协作：StopManaged + 清占用 + 重试该节点；  
  - 选原任务：本节点 failed（或整 run stopped，见 §7-Q3）。

首版若工期紧：**可只做启动预检**（Q1-A），运行中仍 failed + 错误文案提示「请终止管理台对话后重试节点」。

### 4.2 头像上传与 OSS

#### 配置（环境变量，无则上传接口 503）

| 变量 | 说明 |
|------|------|
| `AVATAR_OSS_ENDPOINT` | 如 `oss-cn-hangzhou.aliyuncs.com` |
| `AVATAR_OSS_ACCESS_KEY_ID` | |
| `AVATAR_OSS_ACCESS_KEY_SECRET` | |
| `AVATAR_OSS_BUCKET` | |
| `AVATAR_OSS_PREFIX` | 如 `colleague-avatar/avatars/` |
| `AVATAR_OSS_PUBLIC_BASE` | 可选 CDN/自定义域，拼最终 URL |

**本环境已确认（写入本地 `.env`，勿提交密钥）：**

| 项 | 值 |
|----|-----|
| Endpoint（外网上传） | `oss-cn-qingdao.aliyuncs.com` |
| Bucket | `digital-employee-qd` |
| Public Base（CNAME） | `https://digital-employee-qd.cn-qingdao.taihangcda.cn` |
| Prefix | `avatars/` |
| 内网 endpoint（ECS） | `oss-cn-qingdao-internal.aliyuncs.com`（本机开发用公网） |

密钥仅在仓库根 `.env`；模板见 `.env.example`。`scripts/start.sh` 启动时自动 `source .env`。

依赖：阿里云 OSS Go SDK（如 `github.com/aliyun/aliyun-oss-go-sdk/oss`）。

#### 压缩策略（推荐）

1. **前端**：`<input type=file accept=image/*>` → canvas 最长边 ≤ 512，JPEG quality ~0.82，再 FormData 上传（减小上行）。  
2. **后端**：再解码校验 MIME；用 `image` 标准库 / `nfnt/resize` 或 `disintegration/imaging` 最长边 ≤ 512，JPEG 写出；拒绝非图、>5MB 原文件。  
3. ObjectKey：`{prefix}agent-{id}-{unix}.jpg`。  
4. 成功：`UPDATE managed_agents SET avatar_url=?`；返回员工 JSON。

#### API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin/agents/:id/avatar` | multipart `file`；返回 `{ avatar_url, ...agent }` |
| DELETE | `/api/admin/agents/:id/avatar` | 可选：清空为 NULL（展示默认图）；OSS 旧对象可懒删 |

展示辅助（前端）：

```js
export const DEFAULT_AGENT_AVATAR =
  'https://img0.baidu.com/it/u=890210585,2769039861&fm=253&fmt=auto&app=138&f=JPEG?w=500&h=667'

export function agentAvatarUrl(a) {
  return (a?.avatar_url && String(a.avatar_url).trim()) || DEFAULT_AGENT_AVATAR
}
```

CSS：`.ma-avatar { width:32px; height:32px; border-radius:50%; object-fit:cover; }`

落点：`ManagedAgents` 列表项、详情头、设置预览、复制弹窗预览。

### 4.3 协作节点头像

选员工时（`WorkflowCanvas.updateSelectedData`）：

```js
data.avatar_url = a.avatar_url || ''  // 存原始；展示用 agentAvatarUrl
data.agent_name = a.name
data.engine = a.engine
```

`WfNodes.jsx` Agent 节点：

```jsx
<img className="wf-node-avatar" src={agentAvatarUrl({ avatar_url: data.avatar_url })} alt="" />
```

运行画布 `WorkflowRunGraph` 同源 `data`，一并显示。旧图无 `avatar_url` 的节点：打开编辑再选一次员工即可补齐；或列表加载 agents 时按 `agent_id` 回填（推荐启动编辑时 hydrate，见 TODO）。

### 4.4 关键规则

- 默认头像 URL 仅前端展示用，**不必**写进 DB（空 = 默认）。  
- 上传失败不改旧 `avatar_url`。  
- `force_takeover` 必须 JWT 管理接口；禁止无冲突时误杀。  
- `CLONE_INIT` 占用也算冲突：弹窗文案「正在为副本整理记忆」；强制接管同样 Stop + 清占用（取消 clone job 见现有 `DeleteManaged`/`cancelCloneJob` 模式，接管时应对源员工 `cancel` 总结任务——见 §7-Q4）。

请回复选项（如 `Q1A Q2A ...`）。**未选则按推荐 A 开发。**

### Q1. 冲突检测时机

- **A（推荐）**：仅**启动协作**时预检 + `force_takeover`；运行中再撞车仍节点 failed（文案提示去管理台终止后再重试节点）。实现快、覆盖主路径。  
- B：启动预检 + 运行中 `waiting` 弹窗裁决（体验完整，工作量大一档）。

### Q2. 反向冲突（协作跑着时，管理台提问）

- **A（推荐）**：保持现状：管理台 Ask 遇 WORKFLOW → 409/提示去看团队任务，**不做**二选一弹窗。  
- B：管理台也弹窗：「继续协作」vs「打断协作改对话」。

### Q3. 选「继续原任务」时协作侧行为

- **A（推荐）**：不创建 run（启动场景）；运行中裁决则**仅当前节点 failed**，其它已成功节点保留。  
- B：整次 run 直接 `stopped`。

### Q4. 强制接管时源员工处于 `CLONE_INIT` 总结

- **A（推荐）**：与 DIRECT 相同：Stop + ClearOccupancy；副本若仍 `initializing` 则置 `error`「源被协作接管，总结中断」（可重试初始化）。  
- B：禁止接管 CLONE_INIT，弹窗只允许「继续原任务」。

### Q5. 图片压缩主要在哪一侧

- **A（推荐）**：前端预压 + 后端再压校验（双保险）。  
- B：仅前端压缩，后端只校验尺寸/MIME 后直传。  
- C：仅后端压缩。

### Q6. OSS 未配置时

- **A（推荐）**：上传接口返回明确错误「未配置 OSS」；界面仍可用默认头像，其它功能不受影响。  
- B：无 OSS 时改存本地 `WorkspaceRoot` 静态目录并由后端托管（偏离「上传到 OSS」需求）。

### Q7. Agent 节点头像尺寸

- **A（推荐）**：节点内约 28–32px 圆图，与名称并排。  
- B：更大（40px）作为节点主视觉，名称缩小到下方。

### Q8. 旧协作图无 `avatar_url`

- **A（推荐）**：打开编辑器时按 `agent_id` 从员工列表 hydrate 写入（不强制用户重选）。  
- B：仅展示默认图，直到用户重选员工。
