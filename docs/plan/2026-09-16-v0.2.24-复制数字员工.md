# v0.2.24 复制数字员工

> 状态: **已确认设计 / 开发中**  
> 创建: 2026-09-16  
> 审核: Q1–Q10 全部选 A  
> 来源: NEW_FEATURE  
> 前置: v0.1.3 智能体管理、v0.2.7 占用、v0.2.18 引擎续聊、v0.2.21/22 压缩、v0.2.23 协作持久会话

## 1. 背景

招聘数字员工后，系统提示词、权限、工作区、任务规划等配置往往要「再招一个几乎一样的同事」。现在只能手工再招一遍，且新员工引擎 Session 为空，完全失忆。

产品需要：

1. 一键复制配置，只改名称（头像字段先占位）。  
2. **绝不复用**原员工 `conversations.engine_session_id`，新员工独立引擎会话。  
3. 复制后由**原员工**总结知识/经验/项目背景，再作为**隐藏初始化上下文**交给新员工。  
4. 新员工在隐藏初始化完成前为「初始化中」，不可当普通空闲员工使用。

当前实现要点（设计须贴合，不要另起炉灶）：

- 配置在 `managed_agents`：`rules_prompt`、引擎/`bin_path`、权限四开关、`workspace_path`、`auto_review`、`task_plan_enabled`、定时任务、`folder_id`。  
- 主对话在 `managed_agents.conversation_id` → `conversations`（含 `engine_session_id`）。v0.2.18 起主对话靠引擎 resume，平台不再拼历史。  
- 项目协作另有 `workflow_agent_sessions`，与主会话隔离。  
- 工作状态现有：`idle` / `running` / `waiting` / `error` / `compressing`。  
- 隐藏聊天已有先例：压缩提示 `exclude_from_context=1`；本次还要 **UI 不渲染**（仅排除上下文不够，压缩提示仍会显示）。

## 2. 开发目标

| # | 目标 | 验收 |
|---|---|---|
| A | 复制入口 + 改名 | 选中员工可「复制」；弹窗必填新名称；提交后出现新员工 |
| B | 配置克隆 | 新员工引擎、bin、系统提示、权限、任务规划、自动审核与源一致（定时/工作组/工作区见 §7） |
| C | 独立 Session | 新 `conversation_id`；`engine_session_id` 为空，直到隐藏初始化 Ask 写入**新** session |
| D | 头像预留 | 表字段 + API + 弹窗占位；本次不上传、不展示真实头像 |
| E | 原员工异步总结 | 复制接口立即返回；后台用原员工引擎记忆做总结（不污染双方聊天页） |
| F | 隐藏初始化 | 总结作为新员工第一轮引擎输入；聊天 GET 不返回或前端不渲染 |
| G | 初始化中 | 新员工 `status=initializing`；列表/对话页文案「初始化中」；禁止 Ask/压缩/协作占用；成功后 `idle` |

## 3. 实现范围

### 本次实现

- `POST /api/admin/agents/:id/copy`，body：`{ "name": "必填", "avatar_url": "" }`（avatar 可空，忽略非空校验以外的写入策略见 §7）。  
- `managed_agents.avatar_url` 可空列；列表/详情 JSON 带出。  
- `managed_agents.status` 增加 `initializing`。  
- 新会话：`CreateConversation` + 绑定 `conversation_id`，**不**拷贝源 `engine_session_id` / 消息 / occupancy / `workflow_agent_sessions`。  
- `askManagedCore` 增加「静默轮」：resume 引擎、更新 token/session，**不**向 `messages` 插入 user/assistant（或插入但 `meta_json.kind=clone_init` 且列表过滤）。推荐见 §4.5。  
- 异步流水线：源员工静默总结 → 新员工静默消化 → `idle`；失败 → `error` + `last_error`。  
- 前端：复制弹窗、状态文案、初始化中禁用提问/压缩/解聘确认（解聘是否允许见 §7）。  
- changelog `v0.2.24`；`db/migrate_v0.2.24.sql` + `schema.sql` + `EnsureSchema`。

### 本次暂不实现

- 真实头像上传、裁剪、CDN。  
- 复制项目协作绑定（`workflow_agent_sessions`）。  
- 批量复制、跨引擎复制（Claude→Codex）。  
- 把源聊天记录逐条拷进新会话。  
- 初始化进度 SSE（列表 1.5s/3s 轮询已有 status 即可）。  
- 复制时改权限/工作区（只改名；其它跟源走，除非 §7 选否）。

## 4. 技术设计

### 4.1 数据

```sql
ALTER TABLE managed_agents
  ADD COLUMN avatar_url VARCHAR(512) NULL AFTER name;
```

`status` 仍 VARCHAR，新增取值 `initializing`（不必改 ENUM）。

可选审计（推荐做，一行 JSON 足够）：`messages.meta_json` 或独立不建表。

**明确不拷贝**

| 字段/实体 | 原因 |
|-----------|------|
| `conversation_id` / 消息 | 新会话 |
| `engine_session_id` | 需求硬约束 |
| `status` / `last_error` / `last_run_ms` / `run_started_at` | 新员工从初始化开始 |
| `agent_occupancy` | 占用是运行时态 |
| `workflow_agent_sessions` | 协作记忆属于项目×源员工 |

**拷贝（已确认）**

`engine`, `bin_path`, `rules_prompt`, `allow_write`, `allow_network`, `allow_rm`, `allow_browser`, `auto_review`, `task_plan_enabled`。

**拷贝（待你选，见 §7）**

`folder_id`, `workspace_path`, `schedule_*`。

`CreateManagedAgent` 今天不写 `folder_id` / `auto_review` / `task_plan_enabled`（靠默认）。复制应走专用 `CloneManagedAgent` INSERT，一次写全字段，避免漏拷开关。

### 4.2 API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin/agents/:id/copy` | JWT；创建克隆并启动异步初始化；**立即**返回新员工 JSON（`status=initializing`） |

请求：

```json
{ "name": "小王-副本", "avatar_url": "" }
```

校验：

- 源存在。  
- `name` trim 后非空，长度 ≤128。  
- 源正在 `initializing`：拒绝复制源（避免连环复制未完成体）。  
- 新员工 Ask：`status==initializing` → `409`「员工初始化中」。  
- 协作 `TryAcquireOccupancy`：同样拒绝 initializing。

幂等：不要求；每次 copy 都是新 id。

### 4.3 核心流程

```text
POST copy
  → INSERT 新 managed_agents (status=initializing, conversation_id=新会话, avatar_url)
  → 立即 200 返回
  → go func() 后台（context.Background，与 HTTP 脱钩）:
       1) 源员工 SilentAsk(resume 源 engine_session)
          Prompt: 请用第三人称/条目总结你作为数字员工掌握的重要知识、经验、项目背景、仓库约定、未完成事项。
                  控制在 N 字以内；不要提工具过程；不要问候。
       2) 若源无 session / 无消息：跳过 1)，summary = 「无历史可继承，仅使用系统提示词。」
       3) 新员工 SilentAsk(无 resume，首轮创建新 session)
          Prompt: 【隐藏初始化】你是新员工{newName}，由{srcName}复制配置而来。
                  内化下列背景，之后用自己的身份工作；不要复述本段，不要说「我是复制的」。
                  ---
                  {summary}
       4) 成功：status=idle；失败：status=error，last_error 可读中文
```

原员工总结期间会短暂 `running`（与普通 Ask 相同占用 DIRECT）。若与用户正在聊冲突，见 §7-Q3。

新员工初始化期间保持 `initializing`，即使内部 SilentAsk 会走 runner：对外列表仍显示「初始化中」，不要先打成 `running` 再打回（避免和真人对话态混淆）。实现建议：`askManagedCore` 增加 `statusHold`，SilentAsk 不改写 `initializing`。

### 4.4 独立 Session

- 新 `conversations` 行：`agent_id=新员工`，`engine_session_id=NULL`。  
- SilentAsk 新员工时 `bindMainConv=true`，让 `UpdateConversationEngineMeta` 写入**新** session。  
- 禁止任何 `UPDATE ... SET engine_session_id = 源session`。  
- 回归测试：copy 后两行 session 不等；源 session 不变。

### 4.5 隐藏初始化（聊天页）

**推荐方案 A（静默不落库）**

SilentAsk 不 `InsertMessage`。聊天页天然空白。引擎侧已有 session + 首轮用户消息（总结）在 CLI 历史里。

代价：平台侧看不到初始化原文，排障靠 `last_error` 与日志。

**备选 B（落库但过滤）**

插入 `role=user/assistant`，`meta_json={"kind":"clone_init","hidden":true}`。  
`GET .../messages` 默认 `hidden=0`；管理排障可 `?include_hidden=1`。  
前端双保险：不渲染 `hidden`。

`exclude_from_context` **不要**打在初始化消息上（若落库且将来又改为拼历史会丢记忆）。v0.2.18 主路径不拼历史，过滤主要是 UI。

> 默认按 **A** 写进 TODO；若你在 §7-Q4 选 B 再改。

压缩提示仍显示；clone_init 与压缩提示不是一类。

### 4.6 总结提示词（实现时写入代码常量）

源员工（SilentAsk，resume）：

- 说明：这是系统内部整理，不要当作对用户的回复口吻。  
- 输出：Markdown 短文，建议上限 **1200 汉字**（可截断）。  
- 覆盖：人设要点、常做项目/仓库、权限与工作区习惯、重要结论、进行中事项。  
- 可附带：若 `workspace_path` 下存在 `projects/*/summary.md`（v0.2.23），提示其「可 Read 这些文件再总结」——**仅当源空闲且允许读工作区**。若你担心多一次工具调用拖长初始化，见 §7-Q5。

新员工（SilentAsk，无 resume）：

- 系统提示仍走现有 `policy_prompt` + `rules_prompt`（复制后已相同）。  
- 本轮 user 内容 = 隐藏初始化段 + 源总结。  
- `task_plan_enabled`：初始化轮 **强制关闭拆分**（避免 JSON 计划污染新 session，对齐 v0.2.17 教训）。

### 4.7 前端（`ManagedAgents.jsx`）

- 选中员工标题旁：「复制」（`initializing` 的员工不再提供复制）。  
- 弹窗：新名称（默认 `{原名} 副本`）、头像「即将支持」禁用 input。  
- 列表状态：`initializing` → 「初始化中」（可复用呼吸点，避免与「忙碌中」同色；建议单独灰/蓝文案）。  
- 选中初始化中：输入框 disabled，提示「正在继承同事记忆…」；不显示压缩。  
- 轮询已有，无需新通道。

### 4.8 测试（TDD，本仓库惯例）

- `CopyManagedAgent`：字段拷贝、新 conv、源 session 不变、新 session 空。  
- initializing 时 Ask / occupancy 拒绝。  
- 消息列表不含 clone_init（若选 A 则表中无行）。  
- 初始化失败置 `error`。  
- handler：缺 name → 400。

## 5. 变更影响

| 原设计 | 新设计 |
|--------|--------|
| 只能一键招聘空白员工 | 可从现有员工复制配置 |

| 无 avatar 字段 | `avatar_url` 预留，UI 不启用上传 |
| Ask 必落库聊天消息 | SilentAsk 可不落库 |

**不改** E-bot 首页、协作 Canvas 节点配置（节点仍选 agent_id；复制出的是另一个 id）。

## 7. 待确认事项

请直接回复选项字母（可一行写完，如 `Q1B Q2A ...`）。**未选则开发时按「推荐」实施。**

### Q1. 工作组 `folder_id`

- **A（推荐）**：复制后仍在同一工作组。  
- B：复制后回到「未入组」。

### Q2. 工作区 `workspace_path`

- **A（推荐）**：原样复制（两个同事盯同一仓库，这是最常见分身场景）。  
- B：清空，新员工未绑定工作区。  
- C：弹窗里允许改工作区（超出「只改名」，本次变大）。

### Q3. 源员工正在忙碌（`running` / 协作占用 / `waiting` / `compressing`）时点复制

- **A（推荐）**：仍立即建新员工；总结轮排队，等源 `idle` 后再 SilentAsk（超时如 10 分钟则 `error`「等待源员工空闲超时」）。配置复制不阻塞。  
- B：直接 409，提示先等源空闲。  
- C：不等源 CLI，只用平台 `messages` 做摘要（不调用原员工引擎；记忆可能比 resume 差，但绝不打断源任务）。

### Q4. 隐藏初始化是否落库

- **A（推荐）**：不写 `messages`，聊天空白。  
- B：写入 `meta_json.kind=clone_init`，列表默认过滤。

### Q5. 总结时是否允许源员工 Read `projects/*/summary.md`

- **A（推荐）**：允许（工作区策略本来就能读），提示词写明可以读这些文件。  
- B：禁止工具，只靠引擎 session 记忆，初始化更快、更少授权弹窗。

### Q6. 定时任务 `schedule_*`

- **A（推荐）**：不复制，新员工定时关闭（避免两个同事同一 cron 双发）。  
- B：原样复制。

### Q7. 初始化中能否解聘

- **A（推荐）**：允许解聘（取消后台 goroutine + 删行），避免卡死员工。  
- B：禁止，必须等初始化结束。

### Q8. 新员工名称默认值

- **A（推荐）**：`{原名} 副本`，可改；允许与原名相同。  
- B：必须与原名不同。  
- C：无默认，空着让用户填。

### Q9. 头像字段本次 API 行为

- **A（推荐）**：列 + JSON 输出；copy body 可带 `avatar_url` 但非空也暂存字符串（为以后铺路）；UI 禁用上传。  
- B：列存在但 copy **忽略** `avatar_url`，恒为 NULL。

### Q10. 初始化失败后

- **A（推荐）**：留在 `error`，对话页提供「重试初始化」（再跑总结+注入，不新建员工）。  
- B：自动删除新员工。  
- C：变为 `idle` 但无继承记忆，只当普通新招。
