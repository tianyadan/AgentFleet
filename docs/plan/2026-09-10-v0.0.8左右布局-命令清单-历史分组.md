# v0.0.8 对话左右布局 + 已授权命令清单 + 历史按IP分组裁剪 (E-bot)

> 状态: 已确认设计 / 待开发
> 创建: 2026-09-10
> 来源: FEATURE_CHANGE(体验) + FEATURE_CHANGE(安全可见性) + FEATURE_CHANGE(历史组织)
> 前置: v0.0.7(耗时/打断/E-bot人设)

## 1. 背景

v0.0.7 已具备耗时、打断、E-bot 人设。v0.0.8 是纯体验/整理:

1. **用户与 AI 对话同侧堆叠**,难分辨;应对话左右分明(用户右、E-bot 左)。
2. **分身执行了哪些命令用户心里没数**,尤其授权代理放行了哪些;需要把「已授权/已执行」的命令展示出来,可复制。
3. **命令无解释**,触发 GA 误解;E-bot 需解释所执行命令的作用。
4. **历史按 IP 混在一起**,跨 IP 会话混杂;要按 IP 分组(文件夹式),每 IP 仅留最近 20 条。
5. 长对话的多轮,**在历史里应算一次对话**(争取),不要每次提问都新起一条。
6. 终止/插话按钮现在常驻,很奇怪;应在用户发送消息后才出现。

## 2. 开发目标

1. 聊天区:**用户消息靠右、E-bot 消息靠左**,视觉分明。
2. 后端记录「本会话/全 IP」已授权命令(Bash,含自动放行 + 手动同意),`GET /api/commands` 返回;前端展示清单,可复制。
3. system prompt 增加「执行命令前,先解释该命令的作用」。
4. 历史页:按 `user_ip` 分组成文件夹,组内按 `updated_at` 倒序;每 IP 仅保留**最近 20 个**会话,更旧裁剪。
5. 长对话历史:一次长对话 = 一条会话(conversations 一行,天然如此)。
6. 终止/插话按钮:**仅当本会话有内容(chatLog>0)才显示**,空会话不显示。

## 3. 实现范围

- 数据:复用 `conversations.user_ip`、`messages`;新增**命令清单**用内存(或 messages 中 Bash tool 副产物)。裁剪:后端在 `ConversationsByIP` 时按 IP 每 20 条裁剪(仅删更旧会话,保留最新 20)。
- 接口:新增 `GET /api/commands`。
- 前端:消息左右布局、命令清单抽屉/面板、历史按 IP 分组手风琴、终止/插话条件显示。

## 4. 技术设计

### 4.1 已授权命令记录

- 后端在 `permission.Decide(allow)` 与分类器 `allow`(Bash)时,把命令写入内存 `approvedCommands []string`(上限 200,环形)。
- `GET /api/commands` 返回 `{items:[...]}`。
- 前端在侧栏/面板展示,每条带「复制」按钮。

### 4.2 左右布局

- 样式:`.msg.user { align-self:flex-end; background:#164e63 }`;`.msg.assistant { align-self:flex-start }`;`.chatbox` 用 flex column,气泡按角色对齐。

### 4.3 命令解释(提示词)

- `agent.SystemPrompt` 追加:**"执行任何 Bash 命令前,先用一两句话解释该命令的作用;不要把命令原样丢给它人无解释。"**

### 4.4 历史按 IP 分组 + 每 IP 20 条

- `GET /api/conversations` 已含 `user_ip`;前端按 `user_ip` 分组成手风琴(文件夹),组内按 `updated_at` 倒序。
- 后端裁剪:`ConversationsByIP` 查询后,对**每个 IP** 只保留最新 20 个会话(超过则按 id 删除更旧的,连同其 messages 由外键 CASCADE 删)。实现放 store 或 service。

### 4.5 长对话合并

- 已是:长对话多轮共用同一 `conversation_id` = 一条记录,历史天然一条。无需改。

### 4.6 终止/插话条件

- 前端:`{chatLog.length > 0 ? (loading?终止:插话) : (发送)}` —— 空会话不显示终止,避免突兀。
