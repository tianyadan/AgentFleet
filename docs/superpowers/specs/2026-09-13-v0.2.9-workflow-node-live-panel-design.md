# v0.2.9 Design: 工作流节点运行态面板与双模式重试

配套计划：`docs/plan/2026-09-13-v0.2.9-工作流节点运行态反馈与重试.md`

## 问题

团队编排运行时，节点侧栏几乎只有 status / JSON，智能体 Ask 过程中的工具、Shell、浏览器、权限请求对「任务计划」页不可见。失败后只有整 run「从失败节点重试」，无法区分原参数再跑与带补充指令再跑。

## 目标

1. **运行过程**：当前在做什么、工具调用、Shell、浏览器等（压缩后的事件流）
2. **权限弹窗**：复用现有 Hub + `/api/permissions/pending|decide`
3. **节点运行结果**：本次 attempt 最终输出
4. **节点错误信息**：失败原因 / 错误摘要
5. **重试**：原参数不变，对该节点发起新 attempt，并继续后续依赖
6. **修改要求并重新执行**：输入框内容作为「节点补充指令」（**不是**与该 Agent 闲聊），新 attempt 后重跑该节点及后续

按钮文案必须区分：

| 按钮 | 含义 |
|------|------|
| 重试 | 原参数不变，再执行一次 |
| 修改要求并重新执行 | 带下方补充 Prompt 创建新 attempt |

## 数据流

```
AskManagedIsolated(onEvent) ──► askEventToNodeEvent ──► nodeEventBuf ──► events_json
Perms.Subscribe(convID)     ──► permission/command    ──┘
前端 getRun 轮询(1.5s) 读取 executions[].events_json
前端 permissions/pending?conversation_id= 拉权限卡
```

## API

- `POST /api/admin/workflows/runs/:runId/nodes/:nodeId/retry`
  - body: `{ "extra_prompt": "" }`
  - 空 `extra_prompt` → 重试
  - 非空 → 追加到 `run.input_prompt` 的 `【节点补充指令 · {nodeId}】` 后 `resumeFrom(nodeId)`

## 前端结构

`NodeRunPanel`：过程 / 权限 / 结果 / 错误 / 双按钮 + 补充输入框  
`WorkflowRun`：左执行列表，右侧 `NodeRunPanel`

## 非目标

- 工作流专用 SSE（本版轮询即可）
- 把节点会话并入日常 Agent 聊天
