# v0.2.18 引擎续聊：停拼 20 轮历史

## 1. 背景

Managed Ask 与首页 E-bot 每次把平台 `RecentTurns`（最多 20 轮）拼进 prompt，同时 Claude/Codex 已支持 `--resume` / `resume`。双轨喂上下文导致多轮后 token 膨胀（「一次对话像发了 20 条消息」）。Cursor Agent CLI 亦支持 `--resume <chatId>`，且 `-p --output-format json` 结果含 `session_id`。

## 2. 开发目标

1. **一律不再**拼接平台历史轮次；发送 = 系统提示词 + **本轮用户问题**。
2. 有 `engine_session_id` 则引擎 resume；无则新开会话并落库 session。
3. 覆盖 **Claude / Codex / Cursor**（Managed）与 **首页 E-bot**。
4. **不做**工作经验沉淀；停用 Ask 路径上的 MySQL `MemoryService` 注入（表可留）。

## 3. 实现范围

### 本次实现
- 去掉 `buildManagedHistory` / E-bot `RecentTurns` 注入
- Cursor：`GenericAskMeta` + `--resume` + 解析 `session_id` 写入 conversation
- E-bot：`AskStream` 传入 resume + `onMeta` 持久化 session
- changelog + 单测约定

### 本次暂不实现
- 工作经验 md / grep
- 删除 token 圆环 UI
- 删除 `agent_memories` 表

## 4. 技术设计

| 引擎 | 续聊 | 本轮输入 |
|------|------|----------|
| Claude | `--resume <session_id>` | `--append-system-prompt` + 本轮 question（history=""） |
| Codex | `codex exec … resume <thread_id> <prompt>` | system 规则块 + 本轮 question |
| Cursor | `agent -p --output-format json --resume <id> <prompt>` | 同上 |
| E-bot | 同 Claude Runner | `SystemPrompt()` + 本轮 question |

- `noHook` 轻量调用仍不 resume、不写主 session（保持 v0.2.17）。
- 「新建对话」继续 `ClearConversationEngineMeta`，强制新 session。

## 5. 变更影响

| 原 | 新 |
|----|----|
| history 20 轮 + resume | 仅 resume + 系统提示 + 本轮 |
| Cursor 无 session | 解析并 resume |
| E-bot 无 resume | 绑定 conversation.engine_session_id |
| MemoryService 注入 Ask | 停用 |
