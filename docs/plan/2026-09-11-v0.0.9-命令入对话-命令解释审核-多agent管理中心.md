# v0.0.9 命令入对话 + 命令解释审核 + 多 Agent 统一管理中心 (E-bot)

> 状态: 已确认设计 / 待开发
> 创建: 2026-09-11
> 前置: v0.0.8(左右布局/命令清单/历史分组)
> 范围: 4 项功能(UI 收敛 + 审核增强 + 大模块多Agent管理中心)

## 1. 背景与四项需求

1. **命令入对话而非独立「命令清单」栏**: v0.0.8 把已执行命令放在顶部「命令清单」tab,用户要在单独页翻看,不方便在对话流中审阅。需求: 已执行的命令**直接展示在 AI 对话框的对话流里**(作为一条消息),随对话一起看;菜单栏**不再需要单独「命令清单」tab**。
2. **终止按钮仅对话进行中显示**: 长对话里消息发完后 AI 已停止,「终止」按钮仍占位(置灰)很丑。需求: **仅在对话处于进行状态(loading)时显示「终止」**,空闲时不显示。
3. **命令解释 + 风险审核(AI 二次复核)**: AI 每次要弹窗授权执行命令时,应**再快速调用另一个 AI** 告知当前命令的**含义**与**是否有风险/原因**,与命令一起在弹窗展示,帮助用户决定是否放行。
4. **多 Agent 统一管理中心**: 让多个 agent(codex/cursor/claude…)工作,统一向赛博助理**上报任务进度**;赛博助理可查询;提供前端 GUI 展示多 agent 任务进度。需**可插拔**(抽象 agent 来源)。

## 2. 开发目标

1. 删除「命令清单」tab;已执行命令以对话消息形式出现在 AI 对话框。
2. 「终止」按钮仅 `loading` 时渲染。
3. 权限弹窗展示「命令 + AI 解释含义 + 风险结论/原因」(复用/扩展审核器,或用独立解释器)。
4. 新增**多 Agent 管理中心**: 上报接口 + 存储 + 查询接口 + 前端任务进度面板;agent 来源可插拔。

## 3. 实现范围

### 3.1 命令入对话
- 后端: 现有 `GET /api/commands` + `Hub.AppendCommand` 已记录命令。需把已执行命令**推送到 SSE 对话流**(复用 `permission_auto`/新增 `command` 事件类型),前端以一条 `role: command` 消息插入对话。
- 前端: 移除「命令清单」tab 与 `loadCommands`;把命令事件渲染为对话框内的一条消息(带「复制」)。
- 兼容: 长对话打开时,历史消息里 command 记录在哪?命令当前只存进程内(Hub),重进对话不显示历史命令。**决策**: 命令记录仍进程内(非持久),只对**本次会话期间**发生的命令实时入对话;历史不回溯(见待确认)。

### 3.2 终止按钮条件
- 前端: 发送按钮区 `{loading ? '插话' : '发送'}`,终止按钮 `{loading && <button>终止</button>}`。v0.0.8 已改为 `chatLog.length > 0 &&`,**进一步改为 `loading &&`**(进对话即 loading,含思考/授权期)。

### 3.3 命令解释 + 风险复核
- 复用 `Reviewer`(独立 claude)做**解释与风险**;在 `Ask`(需人工确认)命令时并行/前置调用解释器,产出 `{meaning, risk, reason}`,随 `permission_request` 事件推给前端展示。
- 注意**: 审核器 URL 自锁约束**——reviewer 已是独立进程,解释可在同一 reviewer 调用里一并给出(一条 prompt 返回 含义+风险),不新增调用即可满足「快速调用另一 AI」。对需要弹窗的命令,调用解释器,把结果挂在 `Public` 上。
- 前端: 权限卡片显示 `含义` + `风险[低/中/高]/原因`。

### 3.4 多 Agent 管理中心(新模块)
- 后端新增 `internal/agentmgmt`(store + handler): 
  - `POST /api/agents/tasks` —— agent 上报任务进度`{agent_type, agent_id, task_id, task_name, status, progress, message, payload?}`
  - `GET /api/agents/tasks?agent_type=` —— 查询
  - 可选 `DELETE`/`PATCH` 更新。
- 数据: 新表 `agent_tasks`(见 schema),字段见 §4.4;历史留存最近 N。
- **可插拔**: 以 `agent_type` 字符串区分来源(codex/cursor/claude),上报 JSON 里带 `agent_type`;后端按类型过滤,不做强绑定,未来接新 agent 只需按其能力发 POST。预留 `agent_registry` 或仅用 `agent_type` 自由字符串(轻量可插拔)。
- 前端: 新增「多Agent」tab,GUI 展示各 agent 任务卡片/列表,进度条、状态、更新时间,按 `agent_type` 分组。

## 4. 技术设计

### 4.1 命令入对话(SSevent)
- 后端 `AppendCommand` 处,当命令经允许(Bash allow,含自动+手动)时,构造事件 `{"type":"command","command":"..."}` 推送 SSE(在 handler 的转发循环加该分支)。
- 前端 `parseSSE` 处理 `command` 事件 → `setChatLog` 追加 `{role:'command', content: command}`。
- 移除「命令清单」tab 按钮 + 渲染 + `loadCommands` + `commands` state。

### 4.2 终止按钮
- `<button class="stop">` 渲染条件从 `chatLog.length > 0` 改为 `loading`。

### 4.3 命令解释 + 风险
- 扩展 `ReviewRequest` 增加 `WantExplain bool`(仅弹窗命令开)。`Reviewer.Review` 返回 `Verdict{Allow, Reason, Meaning, Risk}`(Risk: low/mid/high)。
- 更新 `reviewSystemPrompt`: 命令场景输出三行 `ALLOW/DENY`、`含义`, `风险low|mid|high:原因`;非命令沿用旧格式。解析 `parseVerdict` 扩展。
- `Public` 增加 `meaning`、`risk` 字段 → `permission_request` 事件带入 → 权限卡片展示。
- 对 readOnly/deny 命令不需要解释(不弹窗),仅弹窗(ask)走解释。

### 4.4 多 Agent 任务表(schema)
```sql
CREATE TABLE IF NOT EXISTS agent_tasks (
  id         BIGINT        NOT NULL AUTO_INCREMENT,
  agent_type  VARCHAR(64)  NOT NULL,   -- codex / cursor / claude / ...
  agent_id    VARCHAR(128) DEFAULT '',
  task_id     VARCHAR(128) NOT NULL,     -- agent 侧任务ID(幂等键)
  task_name   VARCHAR(512) DEFAULT '',
  status     VARCHAR(32)  NOT NULL,     -- running / done / failed / waiting
  progress  INT          DEFAULT 0,       -- 0-100
  message   TEXT          NULL,            -- 进度说明/汇报
  payload   JSON          NULL,           -- 附加结构化信息(可插拔扩展)
  created_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_agent_task (agent_type, task_id),
  KEY idx_agent (agent_type, updated_at)
) ENGINE=InnoDB;
```
- 幂等: 以 `(agent_type, task_id)` upsert;上报即 insert or update。
- 查询:`GET /api/agents/tasks?agent_type=&status=` → 返回 `{items:[...]}`。

### 4.5 后端结构
- `store`: `UpsertAgentTask`、`AgentTasks`、`AgentTaskTypes`(可插拔枚举)。
- `service`: 透传。
- `handler`: `AgentTasks`(POST 上报)、`AgentTaskList`(GET 查询)。
- `main.go`: 无需大改(h.Register 自动挂载)。

### 4.6 前端「多Agent」tab
- 顶部 nav 加「多Agent」。
- 面板: 按 `agent_type` 分组,每组显示 agent 列表;每个任务卡片含 名称/状态/进度条/最新 message/更新时间。
- 轮询 `GET /api/agents/tasks`(如 3s)刷新。
