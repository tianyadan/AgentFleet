# v0.2.9 工作流节点运行态反馈与重试

## 1. 背景

团队编排运行时节点侧栏几乎无过程反馈；Agent 节点 Ask 时未把 activity/命令/权限透出到任务计划页；失败后只能整 run 从 fail_node 重试，无法按节点区分「原参数重试」与「补充指令再执行」。

## 2. 开发目标

1. 节点面板展示运行过程（工具/Shell/浏览器等 activity）、权限审核、最终结果、错误信息。  
2. 权限继续复用现有 Hub + `/api/permissions/*`。  
3. **重试**：原参数不变，新 attempt。  
4. **修改要求并重新执行**：输入框补充 Prompt，作为节点新一轮执行指令（非闲聊），并重跑该节点及后续依赖。

## 3. 实现范围

### 本次实现
- `node_executions.events_json` 落库实时事件
- `runAgent` 订阅 Ask 事件 + Perms 事件写入 events
- `POST .../runs/:runId/nodes/:nodeId/retry`（`extra_prompt` 可选）
- 前端 `NodeRunPanel`：过程/权限/结果/错误/双按钮

### 本次暂不实现
- 工作流专用 SSE（仍用轮询 getRun + pending）
- 与 Agent 日常会话合并聊天

## 4. 技术设计

- AskManagedIsolated 传入 onEvent；后台 goroutine 订阅 Perms 按 convID 过滤
- 事件节流写库（约 400ms）
- 重试：`extra_prompt` 空=原参数；非空则追加到 run.input_prompt 的「节点补充指令」块后 `resumeFrom`

## 5. 变更影响

| 原 | 新 |
|----|----|
| 侧栏仅 status/json | 过程流 + 权限卡 + 结果/错误 |
| 仅整 run 重试 | 按节点重试 / 补充指令重跑 |
| Ask 事件丢弃 | 写入 events_json |
