# v0.2.5 可维护性治理

## 1. 背景

项目已经形成 Go 后端 + React 管理台的主要能力，但随着智能体、授权、任务进度、DB 查询、版本展示等能力持续叠加，部分入口文件开始变厚。为降低后续维护成本，本版本先沉淀可维护性 TODO，并完成一轮低风险拆分与配置安全收敛。

## 2. 开发目标

- 形成项目可维护性优化清单，明确后续拆分顺序与验收方式。
- 优先拆出低耦合后端接口，减少 `handler.go` 职责密度。
- 将系统提示词构造从总控 service 中独立，降低后续权限与人设规则修改成本。
- 收敛远端数据查询默认配置，避免新环境默认连接真实业务库。
- 清理前端 lint warning，保持管理台基础质量门禁可通过。
- 在管理台「版本」菜单展示最新版本与更新内容。

## 3. 实现范围

### 本次实现

- 新增 `docs/plan/2026-09-13-maintainability-todo.md`，按模块梳理待做 TODO、优化动作、验收方式与当前状态。
- `server/internal/handler/agent_tasks.go`：承接智能体任务进度相关接口。
- `server/internal/handler/db.go`：承接只读 DB 查询相关接口。
- `server/internal/service/prompt.go`：承接系统提示词构造逻辑。
- `server/config/config.go`：`AVATAR_DATA_DB_DSN` 默认值改为空，远端数据查询改为显式启用。
- `web/src/ManagedAgents.jsx`：清理未使用逻辑并稳定依赖，消除 lint warning。
- `web/src/changelog.js`：追加 `v0.2.5`，平台当前版本自动取最新记录。

### 本次暂不实现

- `Store` 按数据域继续拆分。
- `App.jsx` / `ManagedAgents.jsx` 进一步拆 hook 和展示组件。
- 过期注释与历史叙述的全量清理。

## 4. 变更影响

| 原 | 新 |
|----|----|
| `handler.go` 同时承载任务进度与 DB 查询等接口 | 任务进度、DB 查询先拆到独立 handler 文件 |
| `service.go` 包含系统提示词构造 | 提示词构造独立到 `prompt.go` |
| 远端 DB DSN 存在代码默认值 | 默认不启用，必须显式设置 `AVATAR_DATA_DB_DSN` |
| 前端存在 lint warning | `npm run lint` 无 warning |
| 可维护性问题只停留在分析结论 | 文档化 TODO，并进入版本历史 |
