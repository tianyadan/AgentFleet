# v0.2.12 Workflow 服务中断恢复（同进程适配）

## 1. 背景

进程内 Workflow Engine 与 Agent Runtime 同进程。服务重启后双方一并中断；原逻辑启动即把未完成 Run 标 `interrupted`，无法自动自检续跑，也缺少手动「恢复工作流」。

## 2. 开发目标

1. 启动时未完成 Run → `waiting_recovery`（不再立刻 interrupted）
2. 3 分钟恢复窗口内自动节点自检并续跑；超时 → `interrupted`
3. `interrupted` 提供「恢复工作流」按钮（同一套自检逻辑）
4. success+产物在 → 复用；否则新 attempt；依赖/并行规则按确认方案

## 3. 实现范围

### 本次实现
- `waiting_recovery` 状态与启动标记改造
- `SelfCheckNode` / `PlanResume` / `ResumeWorkflowRun`
- 启动自动恢复窗口（3min）
- API + UI「恢复工作流」

### 不实现
- 独立 Runtime/Worker、宕机期间 5s 健康轮询
- 完整进程断点 / Agent 内存恢复
- 改 AskManaged / 权限 / NodeOutput 传递 / 记忆

## 4. 技术设计

```
启动 → MarkWaitingRecovery + 中断未完成 NodeExecution
     → BeginRecoveryWindow(3m)
         → 对每个 waiting_recovery: ResumeWorkflowRun
         → 超时仍 waiting_recovery → interrupted

ResumeWorkflowRun:
  latestByNode → SelfCheck → reusable / needRerun(+传播依赖)
  roots = needRerun 中无 needRerun 前驱
  status=running → executeFromMany(roots)
```

## 5. 状态语义

| 状态 | 含义 |
|------|------|
| waiting_recovery | 重启后正在恢复检查 |
| interrupted | 服务异常导致无法继续（≠ failed） |
| failed | 节点自身执行失败 |
| stopped | 用户终止 |
