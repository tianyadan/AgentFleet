# v0.1.1 历史分页 + 测试服务器治理 + 统计按日分组

> 状态: 已落地
> 日期: 2026-09-11
> 前置: v0.1.0(多 Agent 提示词 / 版本菜单 / 流式中断修复)

## 1. 背景与三项需求

1. **历史分页**: 历史页一次拉全量会话,IP 多时卡顿。改为分页,建议每页 **10** 条,不要一次展示全部。
2. **测试服务器治理**: 配置并持久化测试服务器 `IP/主机、用户名、密码`;功能仅用于收集**正在运行的 docker 容器日志**,诊断运行错误;一次配置随时查看;在服务器执行的**每一条命令**必须前端弹窗展示,并由**另一个 Claude** 翻译含义/确认无害后用户才可放行;该功能有**独立 IP 白名单**(与全局 `AVATAR_ALLOWED_IPS` 分开维护)。
3. **统计重构**: 按**日期**分组,最新日期在前;点击某日展开,展示该日各 **Client IP** 的调用成功次数、失败次数。

## 2. 开发目标

| # | 目标 | 验收 |
|---|---|---|
| A | `GET /api/conversations` 支持 `page`/`page_size`(默认 10),返回 total | 历史页翻页,每页 ≤10 |
| B | 新增「测试服务器」菜单:CRUD 配置(密码不明文回显)、独立白名单、列容器、拉日志 | 非白名单 IP 403;命令必弹窗+AI 翻译;仅 docker 只读日志类命令 |
| C | 统计按日聚合 + 日明细按 IP | 最新日在前;点开见成功/失败 |

## 3. 设计

### 3.1 历史分页

**API**

```
GET /api/conversations?page=1&page_size=10&user_ip=
→ { items: ConvWithPreview[], page, page_size, total }
```

- 排序: `updated_at DESC, id DESC`(全局最新优先)。
- `user_ip` 可选过滤。
- 仍可对每 IP 做上限裁剪(保留现有 TrimIP 逻辑,在分页查询前或定期裁剪)。
- **消息**仍一次拉会话内全部(单会话量通常不大);本版只分页「会话列表」。

**前端**

- 历史页: 列表 + 「上一页 / 下一页」或页码;展示 `user_ip` 标签。
- 可保留按 IP 折叠的视觉,但数据源改为当前页 `items`(不再一次 `ConversationsAllIP` 全量)。

### 3.2 测试服务器治理

#### 3.2.1 数据表

```sql
CREATE TABLE IF NOT EXISTS test_servers (
  id            BIGINT        NOT NULL AUTO_INCREMENT,
  name          VARCHAR(128)  NOT NULL DEFAULT '',
  host          VARCHAR(255)  NOT NULL,          -- IP 或域名
  port          INT           NOT NULL DEFAULT 22,
  username      VARCHAR(128)  NOT NULL,
  password_enc  TEXT          NOT NULL,          -- AES-GCM 密文(Base64),密钥来自 AVATAR_SECRET_KEY
  enabled       TINYINT       NOT NULL DEFAULT 1,
  created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_host_user (host, username)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS test_server_allowed_ips (
  id         BIGINT       NOT NULL AUTO_INCREMENT,
  ip         VARCHAR(64)  NOT NULL,
  note       VARCHAR(255) DEFAULT '',
  enabled    TINYINT      NOT NULL DEFAULT 1,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_ip (ip)
) ENGINE=InnoDB;
```

种子建议: 把 `127.0.0.1` 写入白名单,便于本机调试。

#### 3.2.2 权限

- 中间件/`requireTestServerIP`: 仅当 `clientIP` 命中 `test_server_allowed_ips`(enabled=1) 才放行 `/api/test-servers*`。
- 与全局提问白名单独立: 能提问 ≠ 能管测试机。

#### 3.2.3 命令安全边界(硬约束)

后端维护**命令模板白名单**,禁止任意 shell:

| 动作 | 实际执行的命令形态 | 说明 |
|---|---|---|
| 列运行中容器 | `docker ps --format '{{.ID}} {{.Names}} {{.Status}} {{.Image}}'` | 只读 |
| 拉日志 | `docker logs --tail {{N}} {{container_id}}` | container_id 仅允许 `[a-zA-Z0-9][a-zA-Z0-9_.-]*`,N∈[1,500] |

禁止: `docker exec`、`rm`、管道、`;`、`&&`、重定向、任意 SSH 命令字符串由前端直传。

#### 3.2.4 授权弹窗 + Claude 翻译

流程(复用权限弹窗思路,独立通道以免与对话工具授权串台):

```
前端点「拉日志」
  → POST /api/test-servers/:id/preview {action, args}
  → 后端生成精确 command 字符串
  → 调用独立 Claude(Reviewer 同款)产出 {meaning, risk, harmless:bool}
  → 返回 {request_id, command, meaning, risk}
  → 前端弹窗展示命令 + 翻译;用户 同意/拒绝
  → POST /api/test-servers/commands/decide {request_id, behavior}
  → 仅 allow 且 risk≠high 且 harmless 时 SSH 执行,回传 stdout/stderr
```

- 超时未点 → 拒绝。
- high 风险即使点同意也拒绝(服务端强制)。
- 进程内 Hub 存 pending(可与对话 Perm Hub 分离为 `TestCmdHub`)。

#### 3.2.5 API 一览

| Method | Path | 说明 |
|---|---|---|
| GET/POST | `/api/test-servers` | 列表 / 新建 |
| PATCH/DELETE | `/api/test-servers/:id` | 更新(可改密码)/删除 |
| GET/POST/DELETE | `/api/test-servers/allowed-ips` | 白名单维护 |
| POST | `/api/test-servers/:id/preview` | 生成命令+AI 翻译,进入待确认 |
| POST | `/api/test-servers/commands/decide` | 同意/拒绝并执行 |
| GET | `/api/test-servers/:id/containers` | **经 preview+decide** 或内部走同一闸门后返回运行中容器 |

说明:「列容器」也必须走 preview→弹窗→decide,满足「每一条命令弹窗」。

密码: GET 列表只返回 `password_set: true/false`,永不回传明文/密文。

环境变量: `AVATAR_SECRET_KEY`(密码加密;缺省则用派生默认并打日志警告)。

#### 3.2.6 SSH

- 使用 `golang.org/x/crypto/ssh`,密码认证,超时短(连接 10s,命令 60s)。
- 不落盘 known_hosts 校验可配置 `AVATAR_SSH_INSECURE_IGNORE_HOSTKEY=1`(默认开发方便;文档标明风险)。

### 3.3 统计按日 + IP 明细

**API**

```
GET /api/stats/days
→ { items: [{ date, total, ok_count, fail_count }] }  -- ORDER BY date DESC

GET /api/stats/days/:date
→ { date, items: [{ user_ip, total, ok_count, fail_count }] }
```

SQL 思路: `messages` JOIN `conversations` 取 `user_ip`;  
成功: `status='ok'`; 失败: `status IN ('error','rejected','aborted')` 或 `status<>'ok'`。

**前端**

- 统计页改为日期手风琴(最新在上);点击展开请求日明细表(IP / 成功 / 失败 / 合计)。
- 兼容移除旧「按工作区扁表」或降级为次要视图(本版以日期+IP 为主)。

## 7. 风险

- SSH 到内网机器有横向风险 → 靠独立 IP 白名单 + 命令模板 + AI 翻译 + 人工确认四层闸门。
- Claude 翻译失败时: 弹窗仍展示命令,标注「翻译不可用」,默认不自动放行。
