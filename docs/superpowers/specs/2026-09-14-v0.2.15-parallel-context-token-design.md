# v0.2.15 Design

## Decisions

| Topic | Choice |
|---|---|
| False WORKFLOW busy | Dedupe ready + successor enqueue in `runQueueWaves` |
| Status source | Resume engine session; real context tokens |
| Token task | Per send/interrupt round |
| Ring | Same API as Status (real); refresh on task start/end + every 5s idle/running |
| Folder badges | Green = direct run count; purple = workflow occupancy count |

## Parallel bug

Multi-parent success appends the same successor N times → same wave runs agent twice → second hits occupancy. Fix: `seen` set when building ready and when appending next IDs.

## Engine context

1. Persist `engine_session_id` (and last usage snapshot) when Ask stream emits init/result.
2. `BuildAgentContextReport` / `FetchEngineContext`:
   - Claude: resume session; parse usage + `modelUsage.contextWindow` (prefer slash/context via print if available; else last result + light resume probe)
   - Cursor agent: `--resume` / `--continue` + stream parse
   - Codex: resume/thread when available; else report unsupported with last known
3. Status UI: dashed block, not DB message, not model context.
4. Ring: `used/total` from same fetch; poll 5s.

## Token live

SSE `usage` / session patch during Ask; show beside `ma-thinking`; reset on new send.
