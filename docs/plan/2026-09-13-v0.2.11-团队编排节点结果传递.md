# v0.2.11 团队编排节点结果传递

## 1. 背景

Workflow 仅保证节点执行顺序；下游 Agent Prompt 虽附带 `outputs`，但（1）塞入了**全部**历史节点而非直接上游；（2）仅截断 summary，缺少可交接的 `result`/`artifacts`；（3）未明确「勿重复上游工作」。导致下游重复做上游已完成的事。

## 2. 开发目标

1. Agent 成功后落库结构化节点结果：`status` / `summary` / `result` / `artifacts`
2. 下游启动前只注入**直接上游**结果（并行汇入则全部直接上游并标注来源）
3. Prompt 明确：优先用上游结果、禁止重复、不足才可补充

## 3. 实现范围

### 本次实现
- `NodeResult` 规范化 + `BuildAgentNodeResult`
- `CollectDirectUpstream` + `FormatUpstreamForPrompt`
- `runAgent` / `buildWorkflowAgentPrompt` 改用直接上游
- 单测覆盖链式与并行汇入

### 本次暂不实现
- 跨跳传递（A→B→C 中 C 默认不看 A）
- 传递完整聊天/命令日志

## 4. 技术设计

```
Agent 完成 → BuildAgentNodeResult → output_json + outputs[nodeID]
下游 Agent → CollectDirectUpstream(g, nodeID, outputs) → Format → Prompt
```

`artifacts`：从正文抽取路径/图片引用；无可为空数组。

## 5. 变更影响

| 原 | 新 |
|----|----|
| 全部 outputs 的 summary | 仅直接上游的 status/summary/result/artifacts |
| 无「勿重复」约束 | Prompt 明确交接规则 |
