# v0.2.4 Cursor 密钥、长超时自检与浏览器权限

## 1. 背景

1. Cursor 引擎报 `CURSOR_API_KEY` 无效：父进程（含 Cursor Agent 会话）环境变量泄漏给子进程。  
2. 运行约 15 分钟后 `signal: killed`：`AVATAR_TIMEOUT_SEC` 默认 900s。  
3. 终端被杀后无自检续跑，用户不知状态。  
4. 需「允许操作浏览器」开关 + browser-use 说明。  
5. 设置页胶囊开关居中不齐。  
6. 任务失败时进度条仍停在当前步，无失败标记。

## 2. 开发目标

- 子进程环境剔除 `CURSOR_API_KEY` 等，避免无效 key。  
- 默认/最大超时提升至 **8 小时**（28800s）。  
- 终端被杀后：对话提示自检 → 重调引擎判断是否完成 / 续跑（有限次）。  
- `allow_browser` 胶囊开关 + 系统提示词。  
- 设置行：标题左、开关右。  
- 失败步骤标红并显示 ✕。

## 3. 实现范围

### 本次实现
- `CleanEnv` 扩展 + AskStream 始终 CleanEnv  
- `TimeoutSec` 默认 28800，上限 8h  
- `runWithTerminalRecover` 自检续跑 + SSE/消息提示  
- DB `allow_browser` + store/handler/UI/policy  
- Capsule 同行布局 + 进度 failed_step

### 本次暂不实现
- 无限重试；跨进程 OOM 的系统级防护

## 4. 技术设计

- envStrip 增加 `CURSOR_API_KEY`、`CURSOR_AGENT` 等干扰项。  
- 超时：`config.TimeoutSec` 默认 `28800`；`clamp` 最大 28800。  
- 恢复：错误匹配 `killed` / `signal: killed` / `deadline exceeded` → 插入 `system` 提示 → 自检 prompt 再跑（最多 2 次）。  
- `allow_browser` TINYINT；策略块写入 browser-use 指引。  
- 任务 `fail` 写 `failed_step`；前端 `li.failed`。

## 5. 变更影响

| 原 | 新 |
|----|----|
| 继承父进程 CURSOR_API_KEY | 剔除后启动 agent |
| 默认 15min 杀进程 | 默认最长 8h |
| 被杀即失败 | 自检+有限续跑 |
| 无浏览器开关 | allow_browser |
| 胶囊居中 | 左文右钮 |
| 失败无步骤标记 | 当前步 ✕ 标红 |
