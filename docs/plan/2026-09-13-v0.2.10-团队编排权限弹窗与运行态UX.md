# v0.2.10 团队编排权限弹窗、自动审核与运行态 UX

## 1. 背景

团队编排 Agent 节点等待命令授权时无弹窗（根因：会话 `user_ip=admin`，`/permissions/pending` 按浏览器 IP 过滤导致管理台拉不到）；侧栏权限卡无风险/中文解释；菜单仍称「任务计划」；终止/失败任务入口与节点状态可视化不足。

## 2. 开发目标

1. 团队执行界面弹出与 Agent 对话页同级的授权框（低/中/高风险 + 中文含义）。
2. Canvas Agent 节点配置「命令自动审核」胶囊：开启后 AI 自动放行非敏感命令（sudo/rm 等仍走人工）。
3. 「团队编排」菜单橙色徽标显示待审核命令数。
4. 菜单「任务计划」→「团队编排」，去掉任务计划字眼。
5. 「团队编排」菜单绿徽标显示正在运行的团队数。
6. 手动终止/出错的团队也显示「查看任务状态」；运行页节点成功绿框、失败红框。
7. 节点过程区自动滚到底；状态用彩色小标签。

## 3. 实现范围

### 本次实现
- Admin JWT 下 pending 权限可见；工作流待授权聚合 API + Overlay
- 节点 `data.auto_review` + 引擎 SetAuto
- 菜单改名/双徽标；列表入口；运行页图着色 + 自动滚动 + 状态标签

### 本次暂不实现
- 工作流专用 SSE（仍轮询）
- 改动敏感命令分类规则本身（复用现有 Reviewer/Classify）

## 4. 技术设计

- `PermissionPending`：Bearer 管理员 JWT 时跳过 ClientIP 过滤（或放行 `client_ip=admin`）
- `GET /api/admin/workflows/permission-pending`：仅返回 `node_executions.status=running` 的 conversation 上的 pending
- 前端 `WorkflowPermOverlay` 复用 `PermissionCard`（风险色 + meaning）
- `runAgent`：`auto_review` 节点写 `Perms.SetAuto(convID,true)`
- App 轮询 running 团队数与 workflow pending 数

## 5. 变更影响

| 原 | 新 |
|----|----|
| 工作流授权静默卡住 | 浮层授权 + 菜单橙徽标 |
| 无节点级自动审核 | Canvas 胶囊开关 |
| 任务计划 | 团队编排 |
| 终止/失败难回看 | 均可「查看任务状态」+ 红绿框 |
