# Claude 数字分身(Digital Colleague Avatar)

> 状态: 已确认设计 / 待开发
> 创建: 2026-09-07
> 来源: NEW_FEATURE

## 1. 背景

工作日经常被同事的消息打断:一些人会来问「这个接口如何实现?」「这个计算公式是什么?」「这个配置是谁改的?」。
很多问题都指向**既有代码/文档/配置中的确定性信息**,但本人太忙无法逐条即时回复,导致同事等待、协作效率下降。

需要一个**数字分身**:授权同事通过网页向它提问,它基于**已授权的工作区代码/文档**,以「本人」的视角和知识,自动回答这些偏「查证/解释」类的问题,并对历史问答做记录以便复盘与统计。

形式约束(既定决策):

- 后端用 **Go**(轻量、单二进制、低资源占用)。
- 前端用 **React**(同事浏览器直接访问,界面友好)。
- 存储用 **MySQL**(本地已在 docker 跑 `mysql:8.0`,端口 3306)。
- 大模型调用 **Claude**,支持命令行 `claude -p` 方式唤起,也能走 API。
- **权限必须收敛为只读**:分身只能「读」已授权工作区,绝不能改代码/配置/数据。
- 只读范围 = **已被授权(allowlist)的指定工作区**,未授权的一律拒绝。

## 2. 开发目标

交付一个可本地部署、同事可用浏览器访问的数字分身问答应用:

1. 同事打开网页 → 输入问题 → 后端用授权 Agent 访问已授权工作区 → 返回「本人风格」回答。
2. 所有问答落库,支持历史记录查询与后续统计(热点问题、授权工作区命中率等)。
3. 权限模型明确:未授权工作区不可读;分身行为只有「读」没有「写」。
4. 轻量、易启动:`docker compose` 拉起 MySQL 即可,后端单 Go 二进制。

## 3. 实现范围

- 本次实现:
  - Go 后端 HTTP API(问答、历史记录、授权工作区列表、健康检查)。
  - React 前端(提问框、回答展示、历史记录页)。
  - MySQL 表设计(问答历史、统计所需字段)。
  - `claude -p`/Claude API 调用封装,注入「分身人设 + 权限边界 System Prompt」。
  - 授权工作区 allowlist 配置 + 只读强制边界(文件系统层面只读 tmpdir + 只允许读 allowlist 路径)。
  - `docker compose.yml`(MySQL)+ 后端/前端本地启动脚本。

- 本次暂不实现:
  - 多用户登录/SSO/企业身份系统(先做简单 token 或局域网免登录白名单)。
  - 数据写入类问题(分身不回答、不执行任何写操作)。
  - 权限的精细化(如分字段、分文件级别读权限),仅到「工作区目录级 allowlist」。
  - 前端历史统计图表(先把数据结构留好,图表后续做)。
  - 云端部署/HTTPS/公网暴露。

## 4. 技术设计

- 目录结构(建议):
  ```
  colleague-avatar/
  ├── docs/plan/                     # 本设计文档
  ├── docker-compose.yml               # MySQL8(如有需要扩 redis 等)
  ├── server/                       # Go 后端
  │   ├── main.go
  │   ├── config/                  # 配置: db、claude、授权工作区 allowlist
  │   ├── internal/
  │   │   ├── handler/            # HTTP 路由 + 处理(gin or 标准库)
  │   │   ├── service/            # 问答编排、历史服务
  │   │   ├── agent/             # claude -p / API 调用封装
  │   │   ├── auth/             # 只读授权校验(allowlist + 调用方身份)
  │   │   └── store/           # MySQL 访问(sqlx / gorm)
  │   └── go.mod
  ├── web/                         # React 前端(vite)
  │   ├── src/                   # 页面/组件/API client
  │   └── package.json
  └── scripts/                    # 启动脚本
  ```

- 数据表(草稿):
  - `questions`(问答历史)
    - `id` BIGINT PK AUTO_INCREMENT
    - `username` 提问同事
    - `question_text` TEXT
    - `answer_text` LONGTEXT
    - `answer_source`(agent/source 命中信息,可 JSON)
    - `workspace_path` 命中的授权工作区
    - `status`(ok / rejected / error)
    - `created_at` DATETIME
  - `authorized_workspaces`(授权工作区 allowlist)
    - `id`, `path`(绝对路径), `name`, `enabled`, `created_at`
  - `agents`(可选:分身配置/人设版本,便于统计不同人设效果)
  - `stats` 不单独建表,统计用 `questions` 聚合查询。统计维度:**命中工作区 + 时间**。
  - `agent_config`(分身配置,预留人设/语气入口)
    - `id`, `key`(如 `persona`), `value`(JSON), `updated_at`
    - 人设/语气后期由本人通过该表或配置文件指定,代码不写死。

- 核心流程:
  1. 用户打开 React 页面 → 输入问题 + 同事标识。
  2. Go 后端接 POST `/api/question` → 校验调用方身份。
  3. Service 组装 Claude 调用:
     - System Prompt:分身人设(从 `agent_config` 读取,可配置)+ **只读/权限边界**(仅可访问 allowlist 工作区,禁止写)。
     - 通过 `claude -p` CLI 异步运行(复用本机 Claude 登录/授权)。
     - Agent 只能在这个隔离的、只读的、指向授权工作区的工作目录内检索(类似只读 snapshot / 只读挂载)。
  4. 结果写 `questions`,返回给前端。
  5. 历史页 `GET /api/questions` 分页拉取。

- 关键规则(权限 & 安全,最重要):
  - **只读强制**:Agent 运行时挂在工作目录的只读副本 / 或者给 `claude` 进程注入「绝对禁止写操作 / 禁止 git commit / 禁止 curl 外网」边界;任何写意图直接拒绝。
  - **授权 allowlist**:`authorized_workspaces` 配置的路径才允许被读;授权工作区暂定为:
    - `kfi-cloud-api`
    - `kfi-cloud-admin`
    - `kesong-sales-dashboard`
    - 路径必须 resolve 到绝对路径并做前缀校验,防止 `..` 越权。
  - **调用方身份**:局域网内 IP 白名单校验(仅允许授权网段/主机访问),不做复杂账号体系。
  - **Claude 调用方式**:复用本机 `claude -p`(CLI,复用本人 Claude 登录与授权)。
  - **人设/语气**:预留配置项(经 `agent_config` 表或配置文件),暂不写死,后期由本人指定。
  - **敏感信息**:Prompt 里明确禁止分身泄露密钥/环境变量/内部敏感数据。
  - 历史记录仅本人或授权者可查。

- 已识别局限(claude -p 单会话单工作目录):
  - `claude -p` 每次运行落在**单一工作目录**(`cmd.Dir`),工具权限被约束在该目录内,单会话无法跨授权工作区直接读取其他目录。
  - 当问题指向非当前目录的授权工作区时,Agent 会因工具范围受限而无法读取。可选后续增强:
    - 前端把问题路由到对应工作区(通过 `workspace` 字段定位 1 个工作区运行)。
    - 或让 Agent 在授权**根目录**上运行(可读全部授权工作区)而不是单个子目录。

## 5. 变更影响

- 全新项目,不影响已有仓库。
- 仅复用本机既有基础设施:
  - 本地 docker `mysql:8.0`(3306)新增一个库(如 `colleague_avatar`)。
  - 复用本机 `claude` CLI(若走 `-p` 路径)。
- 建议把授权工作区(如 `kfi-cloud-api` 等)以 **只读形式** 纳入分身可读范围,需与本人确认具体列表。
