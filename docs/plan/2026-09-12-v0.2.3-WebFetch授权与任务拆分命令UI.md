# v0.2.3 WebFetch 授权、任务拆分与命令 UI

## 1. 背景

1. Claude 调用 WebFetch 常报「网络策略拦截」并被自动拒绝。  
2. 任务进度常只有笼统 3 步（理解/执行/整理），出现「正在规划…」等空话。  
3. 甲 `@` 调乙时，乙需授权的命令不弹窗，超时拒绝导致任务中断。  
4. 命令风险/含义展示不清晰；缺少一键复制。

## 2. 开发目标

- 智能体已开启「允许联网」时，WebFetch/WebSearch **自动放行**；关闭则硬拒绝。  
- 执行前产出 **4～8 条具体步骤**，禁止空话步骤。  
- 委托执行时授权请求路由到 **调用方会话**，弹窗展示风险/含义（可标注被调智能体）。  
- 命令框按风险绿/黄/红半透明着色；底部小号含义条；一键复制。

## 3. 实现范围

### 本次实现
- `ApplyAgentPolicy` / Classify 后联网工具裁决
- `PlanConcreteSteps`（LLM + 校验 + 启发式兜底）
- HookSpec `PolicyAgentID` + 委托时 `ConvID=调用方`
- 前端 CmdBlock（风险色 + 含义 + 复制）；PermCard 展示被调方提示

### 本次暂不实现
- Claude 官方账号级网络企业策略（非本仓库可控）的绕过

## 4. 技术设计

### WebFetch
- `allow_network=true` → WebFetch/WebSearch 直接 `Allow`  
- `allow_network=false` → `Deny`（智能体策略）  
- 非管理会话保持原 Ask

### 任务拆分
- Ask 前 `PlanConcreteSteps`；过滤「正在规划/正在执行/正在输出…」等；不足 4 步则启发式补全

### 委托授权
- `invokeOne`：`AVATAR_CONV_ID=caller.ConvID`，`AVATAR_POLICY_AGENT_ID=callee.ID`  
- `HandlePermissionRequest` 用 policy agent 做策略与工作区；Register 仍挂 caller conv 以便 SSE/弹窗

### 命令 UI
- `.cmd-block.risk-low|mid|high` 半透明底色；`.cmd-meaning-bar`；复制按钮

## 5. 变更影响

| 原设计 | 新设计 |
|--------|--------|
| WebFetch 一律 Ask | 有联网权限则 Allow |
| 固定 3 步空话 | 4～8 具体步骤 |
| 委托 hook 用被调方 ConvID | 调用方 ConvID + 被调方策略 ID |
| 命令灰框 + 风险标签混排 | 风险色命令框 + 底栏含义 + 复制 |
