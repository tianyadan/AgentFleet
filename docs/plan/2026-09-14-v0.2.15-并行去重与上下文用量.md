# v0.2.15 并行去重、文件夹徽标与真实上下文用量

## 1. 背景

并行汇合后同节点重复入队导致假失败 `agent busy: WORKFLOW …`。文件夹缺少运行徽标。状态/圆环/token 需基于引擎真实用量（绑会话），而非本地字符估算。

## 2. 开发目标

1. 修复并行后继重复执行导致的假 busy
2. 文件夹标题旁绿/紫小标签显示运行中数量
3. 「状态」按钮：绑定引擎 session 查真实上下文窗口占用
4. 每轮发送独立汇总 token，显示在运行态银色文字右侧
5. 输入框右下角圆环展示**真实**上下文占比；任务起止刷新；运行中/空闲每 5s 刷新（与状态同源）

## 3. 实现范围

- 本次实现：上述 1–5；会话持久化 `engine_session_id`；Claude/Codex/Cursor 适配器；changelog
- 本次暂不实现：跨设备同步引擎会话；计费账单页

## 4. 技术设计

- **并行去重**：`runQueueWaves` 构建 ready / 追加后继时按 `nodeID` 去重
- **会话**：Ask 流式解析 `session_id` + `usage` + `contextWindow`，写入 conversation / agent 元数据
- **状态/圆环**：`GET /admin/agents/:id/context`（或增强 status）优先 `--resume` 当前 session 拉取引擎真实占用；无 session 返回明确错误
- **Token 任务**：一次发送累计本轮 usage；SSE 推送 `usage` 事件；下次发送清零
- **圆环轮询**：前端 5s + 任务起止调用同一 context API

## 5. 变更影响

- `workflow_engine.go` 调度
- `managed_agents` / conversations 字段或 meta
- Ask 流式解析与 SSE
- `ManagedAgents.jsx` UI（文件夹徽标、token、圆环）
