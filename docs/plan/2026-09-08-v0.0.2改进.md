# v0.0.2 改进(流式输出 / Markdown 渲染 / 标题 Evan / 回车发送)

> 状态: 已实现 / 已开发
> 创建: 2026-09-08
> 来源: FEATURE_CHANGE

## 1. 背景

v0.0.1 已完成基础问答(提问/历史/统计 + 只读授权)。使用体验上有 4 处需要改进:

1. 页面标题「我的数字分身」显得 low,改为本人英文名 **Evan**。
2. AI 回答是**一次性**返回,等待久、无反馈,改为**流式输出**(边生成边显示)。
3. AI 回答为 markdown 文本,需**渲染**为富文本(代码块/列表/表格/加粗等)。
4. 提问需要点按钮,希望**按回车即发送**(Shift+Enter 换行)。

## 2. 开发目标

v0.0.2 交付 4 项体验改进,流式不影响历史记录与统计的正确落库。

## 3. 实现范围

- 本次实现:
  - 标题改为 Evan。
  - `/api/question` 改为 **SSE(Server-Sent Events)** 流式返回。
  - 前端用 `marked` 渲染 markdown。
  - textarea 监听 Enter 发送、Shift+Enter 换行。

- 本次暂不实现:
  - 跨工作区读取增强(未指定工作区时的 Agent 定位)。
  - 代码高亮(仅基础样式,暂不引入 highlight.js)。

## 4. 技术设计

- 涉及模块:
  - 后端 `internal/agent`、`internal/service`、`internal/handler`
  - 前端 `web/src/App.jsx`、`web/src/App.css`

- 接口变更:`POST /api/question` → SSE 流式
  ```
  data: {"type":"chunk","content":"..."}    增量文本(换行先转义为 \n)
  data: {"type":"done","id":1,"status":"ok"}
  data: {"type":"rejected","reason":"..."}  未授权
  data: {"type":"error","message":"..."}
  ```
  响应头:`Content-Type: text/event-stream` + `Cache-Control: no-cache` + 每块 `Flush`。

- 关键实现:
  - `agent.AskStream`: `cmd.StdoutPipe()` 逐块(4KB)读取,`onChunk` 回调增量转发;完整文本仍拼接落库。
  - `service.AskStream`: 复用授权校验 + 人设构建,收集完整输出写 `questions` 表,流式与落库并存。
  - 前端: fetch + `ReadableStream` reader,`data:` 行解 JSON,`type=chunk` 增量 `setAnswer`(把 `\n` 反转义)。
  - `marked` 渲染:`dangerouslySetInnerHTML` + markdown 样式(code/pre/table/ul/ol/blockquote)。
  - `onKeyDown`: `Enter && !shiftKey` → 发送。

- 数据表 / 结构: 不变,`questions` 仍存**完整**回答。

## 5. 变更影响

原设计(v0.0.1):`POST /api/question` 一次性 JSON 返回 `{question_text, answer_text, ...}`。
新设计(v0.0.2):`POST /api/question` 返回 **SSE 流**,前端改为流式解析。
影响:
- 后端:`handler.Question` 由 JSON 响应改为 SSE 流。
- 前端:`ask()` 由 `res.json()` 改为读流 + 事件解析。
- 落库逻辑保持不变(仍在 `service.AskStream` 结束后写完整回答)。
- 关联文档 [2026-09-07-Claude数字分身.md](2026-09-07-Claude数字分身.md) 的 `/api/question` 接口描述需更新反映流式。

注意点(已发现,非本次修复):
- 未指定工作区时 `claude -p` 落在首个授权工作区目录运行,可能误读其他目录内容 → 跨工作区读取增强(独立 TODO)。
