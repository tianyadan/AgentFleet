# v0.2.20 任务规划开关与协作 UI

## 1. 背景

1. 数字员工 Ask 前串行调用 `PlanConcreteSteps`（最长约 45s），任务真正开跑偏慢。  
2. 列表「已运行」文案随时间变长，把 meta 挤到第二行，布局坍塌。  
3. 项目协作卡片按钮以文字为主，状态标识弱，功能顺序不直观。  
4. Canvas 上 Merge 节点 `clip-path` 裁掉连接点，形状怪异；侧栏缺少用法说明。

## 2. 开发目标

1. **任务规划可配（默认开）**：对话区底部胶囊开关；关则跳过 AI 规划与任务进度展示，直接执行。  
2. **开关落库**：`managed_agents.task_plan_enabled`，按数字员工持久化（对齐 `auto_review`）。  
3. **固定「已运行」宽度**，时间数字变化不挤垮一行。  
4. **项目协作卡片**：启动/删除 SVG；按钮顺序 启动→编辑→查看任务状态→删除；状态呼吸灯 + 文案。  
5. **修复 Merge 节点**连接点与外形，并在 NodePanel 补充使用说明。

## 4. 技术设计

### 任务规划开关
| 项 | 设计 |
|----|------|
| 列 | `task_plan_enabled TINYINT NOT NULL DEFAULT 1`（在 `auto_review` 后） |
| API | `POST /api/admin/agents/:id/task-plan` body `{enabled:bool}` |
| Ask | `enabled=false` → 不调用 `PlanConcreteSteps`，`tp=nil`，不发 `task_progress` |
| UI | composer 上方 `CapsuleToggle`「任务规划」；关时不渲染 `ma-progress-panel` |

### 运行时间
- `.ma-age-fixed`：`min-width` + `tabular-nums` + `nowrap`

### 项目协作卡片
- 状态文案：运行中 / 空闲中 / 报错（及等待/完成等既有态）+ `.wf-status-dot` 呼吸灯
- 图标：`IconPlay` / `IconTrash`；编辑、查看状态保留文字或轻图标

### Merge
- 去掉会裁切 Handle 的 `clip-path`；左多入 / 右单出 Handle
- 侧栏说明：等待并行分支汇合；`wait_for_node_ids` 可空=全部入边
