# v0.1.4 智能体后台运行与体验

> 状态: 已落地
> 日期: 2026-09-11
> 前置: v0.1.3(智能体管理)
> 来源: FEATURE_CHANGE

## 1. 背景

v0.1.3 智能体管理可用,但切换管理台菜单会卸载面板并中断 SSE;系统提示词常驻编辑区占空间;状态刷新偏慢;无插话;压缩上下文无反馈。需要真正后台跑任务、恢复对话流,并补齐时长/设置/插话体验。

## 2. 开发目标

| # | 目标 | 验收 |
|---|---|---|
| A | 切换页面不中断任务 | 切到历史/统计再回智能体,对话继续流式更新 |
| B | 时长展示 | 列表显示「已创建 X」;运行中显示本次已跑时长;完成后保留上次耗时 |
| C | 提示词设置弹窗 | 主界面无常驻编辑框;右侧设置按钮弹窗修改;下次请求立即用新提示词 |
| D | 状态及时刷新 | 列表 status 约 1–2s 更新,运行中可见 busy |
| E | 插话 | 运行中可发新消息打断当前任务并带新问题重跑 |
| F | 压缩反馈 | 点击后显示「正在压缩上下文…」,完成/失败有结果 |

## 3. 实现范围

- 本次实现:
  - 管理台内保持 `ManagedAgentsPanel` 挂载(隐藏不卸载),SSE 不因切菜单 abort
  - 每智能体会话状态(chatLog/loading/abort)模块级缓存,切换智能体不丢运行态
  - `run_started_at` 字段 + 前端相对时间
  - 设置弹窗改 rules;隐藏主区提示词框
  - 插话(同 E-bot: abort + 重发)
  - 压缩中 UI 状态
  - 列表轮询加快(有 running 时 1.5s)
- 本次暂不实现:
  - 跨浏览器标签页共享运行态
  - 服务端真正的 job 队列(仍依赖前端 SSE;刷新整页会丢流,回落拉 messages)

## 4. 技术设计

### 4.1 后台保活

- `App.jsx`: `view===admin` 时始终渲染智能体面板,`adminMenu!=='agents'` 时 `display:none`
- `web/src/managedAgentSessions.js`: 按 agentId 存 chatLog/loading/abortController/runStartedAt/pendingInterrupt;面板订阅更新

### 4.2 后端

```sql
ALTER TABLE managed_agents ADD COLUMN run_started_at DATETIME NULL;
```

- `SetManagedAgentStatus`: status=running 时写 `run_started_at=NOW()`; idle/error 时保留 last_run_ms,清空或保留 run_started_at(结束清空)
- JSON 返回 `run_started_at`

### 4.3 前端体验

- 列表项: 引擎 · 已创建 · (运行中: 本次 Ns) · (空闲: 上次 Ns) · status 徽章
- 设置按钮 → 弹窗编辑 rules → PATCH
- 插话: loading 时发送 → abort 当前 → 标记打断 → finally 发新问题
- compress: `compressing` 状态文案与禁用

## 5. 变更影响

| 项 | 原设计 | 新设计 |
