# v0.2.22 压缩记忆状态与移除新对话

> 状态: 已确认设计 / 已开发  
> 创建: 2026-09-16  
> 来源: FEATURE_CHANGE

## 1. 背景

1. 压缩（手动/自动）是真实工作负载，但菜单与对话页状态仍显示空闲/忙碌，用户看不见「正在压缩记忆」。  
2. 压缩耗时应计入工作时长（`run_started_at` / `last_run_ms`）。  
3. 引擎 resume 已承担续聊；数字员工「新对话」易误清 session，产品上不再需要。

## 2. 开发目标

1. 新增工作状态 **`compressing` → 文案「压缩记忆」**，管理菜单与对话页均展示。  
2. 压缩期间记录工作时长（与 `running` 同用 `run_started_at`）。  
3. 移除数字员工「新对话」按钮与 `NewManagedChat` / `POST .../new`（E-bot 新建对话保留）。

## 3. 实现范围

### 本次实现
- `status=compressing`；`SetManagedAgentStatus` 对 running/compressing 维持计时时钟  
- 手动/自动压缩同步「压缩记忆」状态与 `last_run_ms`  
- 前端状态文案/样式/对话页展示  
- 删除新对话；`ensure-conversation` 供自动审核补建会话  
- changelog v0.2.22

### 本次暂不实现
- E-bot 压缩状态展示  
- 压缩时长独立统计表

## 4. 技术设计

| 项 | 设计 |
|----|------|
| 状态值 | `compressing`，UI「压缩记忆」 |
| 计时 | active：`IFNULL(run_started_at, NOW())`；结束写 `last_run_ms` |
| 自动恢复 | prev=running → 压完回 running；否则 → idle |
| 去新对话 | 删 `/new`；新增 `POST .../ensure-conversation` |

## 5. 变更影响

| 原 | 新 |
|----|----|
| 压缩中可能显示空闲 | 「压缩记忆」+ 时长 |
| 「新对话」换 session | 移除；ensure 仅补建 |
