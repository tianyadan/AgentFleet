# v0.2.21 引擎原生压缩与自动同步

> 状态: 已确认设计 / 已开发  
> 创建: 2026-09-16  
> 来源: FEATURE_CHANGE（替换平台自摘要压缩）

## 1. 背景

当前「压缩」走平台自摘要（`runManagedEngine` 生成 ≤800 字摘要 → 清库 → 写摘要消息），**不调用** Claude / Codex / Cursor 原生 compact，引擎 session 内上下文仍可能膨胀。  
另：引擎自动压缩时平台 DB 对话历史不同步，UI 与真实引擎上下文脱节。

## 2. 开发目标

1. 点击「压缩」→ 调用引擎**原生**上下文压缩，**保留** `engine_session_id`。  
2. 平台 DB 该会话消息**全量删除**，再写入一条系统提示：「上下文已由引擎压缩，会话已保留」。  
3. 压缩后下一轮对话**强制重新带上**数字人系统提示词 / 设置（`needs_system_reinject`）。  
4. 引擎自动压缩（Claude / Cursor / Codex）同步执行同一套平台清库逻辑。  
5. 覆盖数字员工管理页 + 首页 E-bot 长对话。

## 3. 实现范围

### 本次实现
- 重写 `CompressManagedChat`：原生 compact + 清库 + 系统提示 + reinject 标记  
- E-bot：`POST /api/conversations/:id/compress` + 长对话 UI「压缩」按钮  
- Claude：`--settings` 增补 `PreCompact` / `PostCompact` → `avatar-hook` → 后端同步  
- Cursor：Ask 路径注入工作区 `.cursor/hooks.json` 的 `preCompact`（指向 hook）  
- Codex：Ask 路径注入 hooks（或解析 JSONL compaction 事件）→ 同一同步 API  
- `conversations.needs_system_reinject`；Ask 消费后清零  
- changelog v0.2.21

### 本次暂不实现

## 4. 技术设计

### 4.1 核心流程（手动）

```
POST compress
  → 读 conversation + engine_session_id + engine 类型
  → 有 session：EngineCompact(bin, dir, engine, sessionID)  // 如 resume + "/compact"
  → SyncPlatformAfterCompact(convID)：
       DELETE messages
       INSERT assistant「上下文已由引擎压缩，会话已保留」
       SET needs_system_reinject=1
       （不碰 engine_session_id）
```

无 session：仅 SyncPlatformAfterCompact（平台历史对齐；引擎侧无可压）。

### 4.2 自动压缩同步

| 引擎 | 监听方式 | 回调 |
|------|----------|------|
| Claude | `--settings` 注册 PreCompact + PostCompact | hook → `POST /api/permissions/compact-sync` |
| Cursor | 工作区 `.cursor/hooks.json` preCompact | 同上 |
| Codex | PreCompact/PostCompact（config/hooks 注入）+ JSONL `contextCompaction` 兜底 | 同上 / Ask 流内直接 Sync |

`avatar-hook`：若 `hook_event_name` ∈ {PreCompact, PostCompact, preCompact} → 调 compact-sync（不阻塞压缩；PostCompact 优先做清库，PreCompact 也可幂等 Sync）。

### 4.3 下次 Ask 重带系统提示

- 列：`needs_system_reinject TINYINT NOT NULL DEFAULT 0`  
- Managed / E-bot Ask：若为 1，在 system prompt 前加「【压缩后续聊】…」强化段，并 `SET needs_system_reinject=0`  
- 本就每轮发送 `BuildAgentSystemPrompt` / E-bot `SystemPrompt`；标记保证压缩后**至少一轮**显式强化

### 4.4 引擎 Compact 调用约定

| 引擎 | 命令形态（headless） |
|------|----------------------|
| Claude | `claude -p "/compact" --resume <session_id>`（工作目录=员工 workspace） |
| Cursor | `agent -p --output-format json --resume <id> "/compact"` |
| Codex | `codex exec … resume <thread_id> "/compact"` |

失败则返回错误，**不**清库（避免引擎未压、平台已空）。

### 4.5 接口

- 保留 `POST /api/admin/agents/:id/compress`  
- 新增 `POST /api/conversations/:id/compress`（E-bot，校验归属）  
- 新增 `POST /api/permissions/compact-sync`（hook 调用；body: conversation_id, trigger, session_id）

## 5. 变更影响

| 原设计 | 新设计 |
|--------|--------|
| 平台摘要模型压一轮 | 引擎原生 `/compact` |
| 清库后写「📦 上下文已压缩:+摘要」 | 清库后写固定系统提示 |
| 不监听自动压缩 | Hook / 事件同步清库 |
| 仅数字员工有压缩 | + E-bot 长对话 |
| 无 reinject 标记 | `needs_system_reinject` |
