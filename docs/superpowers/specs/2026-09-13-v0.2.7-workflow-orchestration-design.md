# v0.2.7 Design: 团队编排与智能体占用 / 记忆

> 状态: 待用户审阅  
> 前置确认: 方案 2 模块拆分；Condition=表达式优先(AI 预留)；Canvas=`@xyflow/react`；Memory=轻量 Top3～5 + MemoryService；Runtime=进程内 DAG + 全量落库，重启标 `interrupted`

## 1. 目标与非目标

### 目标
- 「任务计划」：Workflow 列表 + React Flow Canvas + 运行详情
- 节点引用现有 `managed_agents`，不复制配置
- 节点类型：Start / Agent / Human Review / Condition / Parallel / Merge / End
- 单 Agent 单主任务占用 + 忙碌来源展示与跳转
- 节点独立会话，复用 AskManaged / permission / agent_tasks / command_audits
- 节点结束后写入 `agent_memories`，日常 Ask 经 MemoryService 召回

### 非目标（本版不做）
Loop、子工作流、Cron/Webhook、自动生成 DAG、Marketplace、服务重启自动续跑、Condition AI 判定实现、全局向量库

## 2. 架构

```
UI (workflow/*) ──REST/SSE──► handler/workflow*.go
                                 │
                    service/workflow_*.go  (CRUD + DAG engine)
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
  AskManaged / Runner      OccupancyService        MemoryService
  permission Hub           (DIRECT/WORKFLOW/       (retrieve TopK
  agent_tasks              INVOKE/SCHEDULE)         + write summary)
         │                       │                       │

```

原则：不新造第二套 Agent Runtime；不把 Canvas 塞进 `ManagedAgents.jsx`。

## 4. 占用规则

| 来源 | 行为 |
|------|------|
| DIRECT | 占用中则拒绝启动，返回 occupancy |
| WORKFLOW | 占用中则该节点不得抢锁；Run 可 waiting 或失败策略见下 |
| INVOKE (`@`) | 保持现有 `acquireAgentRun` 排队 / `waiting` |
| SCHEDULE | 与 DIRECT 相同：冲突则跳过/记日志，不抢占 |

Workflow Agent 节点：执行前 `Occupancy.TryAcquire(WORKFLOW, ...)`；结束后 Release。  
AskManaged(DIRECT) 入口同样 Acquire；与现有 `runs` map 对齐（持锁期间写入 occupancy）。

## 5. DAG 执行器

- `StartRun`：校验图、创建 run=`running`、后台 goroutine
- 按拓扑/边推进；Parallel 扇出；Merge 等配置前置全部 `success`
- Condition：解析表达式（`==` `!=` `>=` `contains` + `and`/`or`），上下文=上游 `output_json`（及文本兜底字段）
- Human Review：run=`waiting`，API 通过/驳回/终止；驳回按 `reject_target_node_id` 新 attempt
- Agent 节点：新建 conversation → AskManaged（或等价封装，注入节点任务 prompt）→ 写 output_json / memory
- 任一必要节点最终失败且不可自动继续 → run=`failed`，记录 fail_node/reason/progress
- 进程退出：未完成 run → `interrupted`（≠ failed/stopped）
- **重试**：从失败节点起；成功且仍有效的前置不重跑；并行只重试失败分支；成功分支保留输出；改上游输入/配置 → 标记受影响下游失效，要求从该点重跑

## 6. MemoryService

```go
type MemoryService interface {
  Write(ctx, agentID, mem) error
  Retrieve(ctx, agentID, query string, limit int) ([]Memory, error) // Top 3～5
}
```

- v0.2.7：`Retrieve` = title/summary 关键字相关性（简单分词/LIKE 打分）
- AskManaged 组装 prompt 时调用，注入少量摘要块
- 不把完整 workflow 对话并入日常 history

## 7. API（草案）

- `GET/POST /api/admin/workflows`
- `GET/PATCH/DELETE /api/admin/workflows/:id`
- `POST /api/admin/workflows/:id/runs` — 启动（body: input_prompt）
- `GET /api/admin/workflows/runs/:runId`
- `POST /api/admin/workflows/runs/:runId/stop`
- `POST /api/admin/workflows/runs/:runId/retry` — 从失败节点重试
- `POST /api/admin/workflows/runs/:runId/review` — approve / reject(+prompt) / abort
- `GET /api/admin/workflows/runs/:runId/nodes/:nodeId/executions`
- `GET /api/admin/agents/:id` — 响应含 `occupancy`（若有）

节点会话消息复用现有 `GET /api/admin/agents/:id/messages?conversation_id=`（若无则扩展 query）。
