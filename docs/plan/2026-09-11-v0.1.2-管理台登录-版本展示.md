# v0.1.2 管理台登录 + 版本展示

> 状态: 已落地
> 日期: 2026-09-11
> 前置: v0.1.1(历史分页 / 测试服务器治理 / 统计按日分组)
> 来源: NEW_FEATURE(内外边界拆分) + FEATURE_CHANGE(版本菜单迁入管理台)

## 1. 背景

E-bot 此前对外对话与对内管理能力混在同一前端壳(提问 / 历史 / 统计同栏)。需要划清边界:访客只对话;管理员登录后进入管理台。登录能力已在本迭代实现,需沉淀为正式版本文档,并恢复「版本变更记录」展示:管理台可见当前版本与分页历史;客户首页底部展示当前版本号。

## 2. 开发目标

| # | 目标 | 验收 |
|---|---|---|
| A | 管理员 JWT 登录,对话/管理双通道 | 未登录可提问;登录进左菜单管理台;历史/统计需 JWT |
| B | 管理台展示当前版本号 | 顶栏或明显位置显示如 `v0.1.2` |
| C | 管理台「版本」菜单恢复变更记录,支持分页 | 列表按版本倒序;上一页/下一页 |
| D | 客户首页底部展示当前版本 | 对话页 footer 显示当前版本 |

## 3. 实现范围

- 本次实现:
  - 单管理员 JWT(`AVATAR_ADMIN_*` / `AVATAR_JWT_*`);login / me / logout
  - 历史、统计、命令清单、测试服务器接口需 Bearer JWT
  - 前端登录弹窗 + 管理壳;`/api/db`、`/api/agents` 保持公开(Agent curl)
  - `changelog.js` 追加 v0.1.2;`CURRENT_VERSION` 导出
  - 管理台顶栏版本号 +「版本」菜单分页
  - 对话页底部版本号
- 本次暂不实现:
  - 用户表 / 改密 / HttpOnly Cookie
  - Agent/任务/备忘录/密码/服务器/数据分析真实业务页
  - 对外对话提示词能力收窄
  - 变更记录后端 API(仍用前端静态 `CHANGELOG`)

## 4. 技术设计

### 4.1 管理台登录(已实现要点)

- 配置:`AdminUser`/`AdminPass`/`JWTSecret`/`JWTTTLHours`
- `internal/auth`: `IssueToken` / `ParseToken` / `RequireAdminJWT`
- 公开: question、建会话、workspaces、permissions、db、agents、health
- 需 JWT: conversations 列表/消息、stats*、commands、test-servers*
- 前端:`avatar_admin_token` localStorage;view `chat|admin`

### 4.2 版本数据

- 文件:`web/src/changelog.js`
- `CHANGELOG` 数组顶部追加新版本
- `export const CURRENT_VERSION = CHANGELOG[0]?.version || 'v0.0.0'`
- 分页:前端切片,默认每页 **5** 条版本记录

### 4.3 前端展示

- 管理台顶栏:`E-bot 管理台 @user · v0.1.2`
- 左侧菜单新增「版本」(建议放在统计下方或菜单底部)
- 版本页:复用既有 `.version-card` 样式 + pager
- 对话页:`<footer class="app-footer">当前版本 v0.1.2</footer>`

## 5. 变更影响

| 项 | 原设计 | 新设计 |
|---|---|---|
| 顶栏 Tab | 提问 / 历史 / 统计 | 提问 + 登录/管理台 |
| 历史/统计 | 公开可见 | 仅管理台 + JWT |
| 版本菜单 | v0.1.0 曾在公开壳 | 迁入管理台,带分页 |
| 客户首页 | 无版本号 | 底部展示 `CURRENT_VERSION` |
| `/api/db`、`/api/agents` | 公开 | 仍公开(Agent curl 依赖) |

影响模块:`server/config`、`server/internal/auth`、`handler.Register`、`web/src/App.jsx`、`App.css`、`changelog.js`
