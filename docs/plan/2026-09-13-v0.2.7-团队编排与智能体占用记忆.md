# v0.2.7 团队编排与智能体占用记忆

## 1. 背景

已有智能体管理、AskManaged、跨智能体 `@`、权限、任务进度等能力；「任务计划」菜单尚未实现。需要在不复制 Agent、不新造 Runtime 的前提下，用可视化编排把现有智能体组成可复用团队 SOP。

## 2. 开发目标

1. 任务计划：编排列表 + React Flow Canvas + 运行/历史。  
2. 引用 `managed_agents`；支持顺序、并行、人工审核、条件、合流、失败重试。  
3. 单 Agent 单主任务占用；忙碌展示来源并可跳转。  
4. 节点独立会话复用现有执行/权限链；结束后沉淀长期记忆并在日常 Ask 召回。

## 3. 实现范围

### 本次实现
- Workflow CRUD + Canvas（7 类节点）
- 进程内 DAG + Run/NodeExecution 全量落库
- 表达式 Condition（AI 判定仅预留）
- Human Review / Parallel / Merge / 失败重试规则
- `agent_occupancy` + 管理页忙碌来源
- `agent_memories` + MemoryService Top3～5
- 独立 `handler/service/store/workflow*` 与 `web/src/workflow/*`

### 本次暂不实现
- 重启自动续跑、Loop/子流程/Cron/Webhook、Condition AI、自动生成团队、Marketplace

## 4. 技术设计

详见：`docs/superpowers/specs/2026-09-13-v0.2.7-workflow-orchestration-design.md`

要点：
- 执行调用现有 AskManaged；权限/审计/策略不改
- `@` 仍排队；DIRECT/WORKFLOW/SCHEDULE 冲突拒绝或跳过
- 未完成 Run 进程退出 → `interrupted`
- 迁移：`db/migrate_v0.2.7.sql`

## 5. 变更影响

| 原 | 新 |
|----|----|
| 任务计划空壳 | Workflow 列表/编辑/运行 |
| 仅 status 忙碌 | + occupancy 来源与跳转 |
| Ask 无团队记忆 | MemoryService 注入摘要 |
| 无团队 SOP | 可保存重复执行的编排 |
