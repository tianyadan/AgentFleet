# v0.2.2 跨智能体调用与进度状态

## 1. 背景

多智能体彼此孤立，无法在对话中协作；任务进度区为空且展示技术向上报提示；列表「已创建」语义不符；设置页开关与「先开再配」项默认展开，不够干净。

## 2. 开发目标

1. `@` 选中其他智能体，由平台并行编排调用；调用方引用展示 + 汇总；被调方分割线摘要（谁调用谁异步总结），不进入被调方模型上下文。
2. 平台执行前拆分任务，对话框底部常驻进度条，去掉 `/api/agents/tasks` 用户可见提示。
3. 「已运行」时长；状态展示：空闲中 / 忙碌中 / 错误 / 等待中。
4. 设置/创建：胶囊开关；定时与工作区限制关闭时隐藏配置项。

## 3. 实现范围

### 本次实现

- 前端 `@` 提及选择器与引用/小窗/折叠 UI
- 后端 mention 解析、并行委托、排队、汇总轮、异步摘要写入
- `messages.exclude_from_context`（及必要 meta）
- 平台任务规划 + `agent_tasks` 更新 + 底部常驻进度条
- 状态中文映射与「已运行」fmtAge
- `AgentPolicyFields` 胶囊 + 条件展开

### 本次暂不实现

- 嵌套 `@`（乙再调丙）
- 前端纯编排 / 模型自由工具互调
- 浏览器原生选绝对路径文件夹

## 4. 技术设计

### 模块

- `web/src/ManagedAgents.jsx`：mention UI、进度常驻、状态文案、设置胶囊
- `server/internal/service/managed_agents.go` / 新 `invoke.go`：委托流水线
- `server/internal/service/task_plan.go`：拆步与进度更新
- `server/internal/store`：消息 exclude、waiting 状态、tasks
- `db/migrate_v0.2.2.sql` + `schema.sql`
- `web/src/changelog.js`：v0.2.2

### 核心流程（`@`）

```
用户发送 → 解析 @mentions
  → 规划任务步骤(落库) → 并行委托(忙则排队 waiting)
  → 调用方 SSE: invoke_status / invoke_result(带 callee_id)
  → 全部完成 → 折叠引用 → AskManaged(甲) 汇总
  → 异步: 甲为每个 callee 写 invoke_divider(exclude_from_context=1)
```

### 关键规则

- 被调完整输出只在调用方；callee 页仅分割线。
- RecentTurns / history 过滤 `exclude_from_context=1`。
- 答案强制按 `callee_id` 分区，禁止合并为一条无主气泡。

## 5. 变更影响

| 原设计 (≤v0.2.1) | 新设计 (v0.2.2) |
|------------------|-----------------|
| 智能体互不调用 | 平台编排 `@` 并行委托 |
| 任务靠外部 curl，UI 折叠+API 提示 | 平台拆步，底部常驻进度条 |
| 「已创建」+ 英文 status | 「已运行」+ 中文四态 |
| checkbox + 定时默认展开 | 胶囊开关 + 关则隐藏配置 |

影响：AskManaged 入口、消息表、agent 状态机、ManagedAgents 对话/设置 UI。
