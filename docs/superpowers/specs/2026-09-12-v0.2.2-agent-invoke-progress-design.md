# v0.2.2 跨智能体调用 · 任务进度 · 状态与设置 UI

日期: 2026-09-12  
状态: 设计已确认（§1–§4），待实现

## 背景

管理台已有多引擎智能体（Claude / Codex / Cursor），但彼此孤立；任务进度依赖外部 curl 上报且 UI 展示技术空提示；状态文案混乱；设置页开关与「先开再配」项不够干净。

## 目标

1. 在一个智能体中通过 `@` 并行调用其他智能体；结果强制隔离；调用方引用展示 + 汇总；被调方仅分割线摘要且不进 LLM 上下文。
2. 执行前平台拆分任务；对话框底部常驻进度条；去掉 API 上报提示文案。
3. 「已运行」时长；状态：空闲中 / 忙碌中 / 错误 / 等待中。
4. 设置/创建页：胶囊开关；依赖项关闭时隐藏配置块。

## 已确认决策

| 项 | 决策 |
|----|------|
| 调用机制 | 平台编排直调（方案 1） |
| 调用方是否再跑 | 先并行调被调方 → 引用展示 → 甲汇总 |
| 多 `@` | 并行；结果强制按 callee 隔离；小窗状态 → 完成后折叠 |
| 被调方忙碌 | 排队，展示「等待中」 |
| 被调方分割线摘要 | 谁调用谁总结：甲异步为每个被调方写摘要 |
| 任务进度 | 平台先拆步再执行，落库 `agent_tasks` |
| 嵌套 `@` | 本版不做，委托正文中的 `@` 当普通文本 |

## 架构

### `@` 委托流水线

1. 前端：输入 `@` 弹出智能体列表（排除自己）；插入带稳定 id 的 mention token。
2. 后端解析 mentions → 为调用方创建/更新任务步骤 → 并行委托（忙则排队）。
3. SSE/存储事件带 `callee_id`；调用方 UI：迷你状态窗 → 完成后折叠引用块。
4. 甲汇总轮：结构化材料（各 callee 名 + 结果）→ `AskManaged(甲)`。
5. 异步：甲为每个 callee 生成短摘要 → 写入 callee 会话 `role=invoke_divider`（或等价）且 `exclude_from_context=1`；`RecentTurns` 过滤。

### 任务进度

- 发送后先规划 3–8 步（引擎轻量 JSON 或兜底步骤），再执行。
- UI：底部常驻进度区；无任务时「暂无进行中的任务」；禁止展示 `/api/agents/tasks` 提示。

### 状态与时长

- 文案「已运行」基于 `created_at`；fmt：分 / 时 / 天。
- 映射：`idle→空闲中`，`running|busy→忙碌中`，`waiting→等待中`，`error→错误`；插话归入忙碌中。

### 设置 UI

- 布尔项胶囊开关；定时 / 工作区限制：开才渲染下级表单。

## 数据变更（建议）

- `messages`：`exclude_from_context TINYINT DEFAULT 0`；可选 `meta JSON`（invoke 元数据）。
- `managed_agents.status` 增加 `waiting`。
- 迁移文件：`db/migrate_v0.2.2.sql`。

## 非目标

- 嵌套委托、前端纯编排、依赖模型自由互调、浏览器原生绝对路径选夹。

## 测试要点

- 单 `@` / 多 `@` 并行结果不串台。
- 被调方忙碌排队与 waiting 文案。
- 分割线可见且不进 callee history。
- 进度条常驻且无 API 提示。
- 设置开关显隐与胶囊样式。
